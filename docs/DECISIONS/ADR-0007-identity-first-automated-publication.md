# ADR-0007：身份优先的自动发布与例外处理

- 状态：已接受
- 日期：2026-07-15

## 背景

首轮两条真实公开事件均经过人工批准，但审批动作没有发现失效深链接和来源日期缺失。逐条人工点击既不能替代链接、日期、Schema、重复和来源一致性检查，也无法扩展到数百家公司。

## 决定

1. 人工资源优先用于公司身份锚点。系统先核验统一社会信用代码、工商全称、注册地、官方域名、曾用名和品牌/母子公司关系；无法唯一解析时进入身份审核队列，且不得生成公司事件。
2. 身份已验证的例行公开事件由版本化确定性策略处理。来源可访问、来源等级和可信度满足配置、证据存在且未命中异常规则时，事务内自动发布并更新快照。
3. 链接不可用、来源较弱、可信度不足、高或极高风险、来源冲突、严重指控或字段异常的记录保存为 `unconfirmed_lead`。线索可以在私有界面展示，但不进入已确认事件、风险结论或公司快照，也不默认创建人工任务。
4. 人工复核改为按需动作：只有身份或组织关系无法解析时强制进入队列；未确认线索只有在用户需要形成正式判断、纠错或撤回时才复核。
5. 每个事件保存发布路由、策略版本和可解释原因。自动发布不表示人工背书；原始证据和不确定性必须继续展示。
6. URL 检查属于外部读取，受 `EXTERNAL_CALLS_ENABLED` 控制；关闭时记录为未检查并降级为未确认线索。同步用户查询仍只读取数据库。

## 影响

人工工作量从逐条审批收敛到身份例外；日常质量问题由程序在发布前阻断。代价是必须维护身份主数据、来源访问检查、策略版本和未确认线索展示，并持续监控自动发布准确性。严重负面不会被自动升级为已确认事实，但可以作为带明确标签的线索及时出现。

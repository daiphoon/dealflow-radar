# ADR-0016：授权数据明细与平台证据详情

- 状态：已接受，待代码 PR 验收
- 日期：2026-08-27
- 关联：ADR-0004、ADR-0009、ADR-0010、ADR-0015

## 背景

按需研究已能返回天眼查六大模块的结构化响应，但首版只保存数量概览，导致页面对用户的信息价值不足。同时，供应商返回的公司根链接可能只是天眼查首页，不能当成可复核的“公开来源链接”。实际缓存已经包含股东、招投标和工商历史等第一页明细，可以在不增加外部调用和模型 Token 的前提下提升展示质量。

## 决策

1. 平台使用已授权结构化响应生成一份最小、可展示的证据详情快照，与事件证据引用关联；供应商完整原始响应仍保留在受限缓存中。
2. 证据详情只允许附着在无个人或机构 owner 的 `platform_shared` 证据上。个人、机构私有证据即使含有类似字段，也不得通过平台证据详情接口读取。
3. 对用户只投影业务必要字段，当前包括股东、招投标、工商变更、知识产权计数与评分、风险概览和人员概览。手机、邮箱、供应商内部 ID 和完整原始响应不进入展示快照。
4. 返回 0 条的模块不生成事件；旧版已生成的零记录概览在缓存重放时改为 `retracted`，但不物理删除。
5. 风险和人员数量只表示“待核实记录概览”，事件保持 `candidate`、`direction=unknown`、`risk_severity=none`；人员数量不自动生成高风险结论。
6. 天眼查首页不展示为“公开来源链接”。平台证据详情是主要复核入口；供应商企业页或单条记录 HTTPS 链接只作补充，并提示可能需要供应商账户或会员权限。
7. 相同模块概览使用稳定指纹。缓存重放更新原概览而不重复新建；如历史遗留多条活跃概览，保留当前记录并撤回重复记录。旧证据引用保留但不再展示，以保留历史。

## 运行与成本边界

- 首次生产回填必须优先重放已有私有缓存，预期天眼查新增调用为 0，模型 Token 为 0。
- 风险、诉讼等如只有数量，本里程碑不自动下钻。未来只对非零、用户需要且通过缓存、预算和去重闸门的类别调用明细接口。
- 同步搜索和公司详情仍只读 PostgreSQL，证据详情接口不调用供应商或模型。

## 非目标

- 不重新查询当前公司；
- 不保存或展示完整供应商响应；
- 不用模型改写或推断事实；
- 不自动下钻诉讼、处罚或其他风险明细；
- 不修改个人、机构和平台的作用域边界。

## 验收

1. 既有股东、招投标和工商变更缓存能零外部调用生成结构化详情；
2. 联系方式、供应商内部字段和私有证据无法通过公共详情接口读取；
3. 零记录不展示，人员不自动高风险，风险仅为待核实概览；
4. 天眼查首页被标记为不可定位，平台内详情可阅读；
5. 迁移、RLS、后端、前端生产构建和缓存重放幂等测试通过。

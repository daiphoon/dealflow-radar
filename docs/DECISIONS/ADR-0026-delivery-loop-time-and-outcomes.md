# ADR-0026：事项动作时间、阶段关联与部分结果

- 状态：依据负责人 2026-09-24 对《原始股雷达：端到端事项交付闭环改造指令》的本地实施授权。
- 补充 ADR-0025；保留技术栈、已有权限、费用上限和人工确认边界。不代表批准真实调用或上线。

1. `occurred`、`disclosed`、`planned` 分槽保存原文、精度、引用和解析版本。年/月仅保留区间，缺年份保持未知；旧 `date` 只读适配，不补造旧语义。`date` 兼容输出仅指发生时间。当前时间投影重新判断是否历史，历史观测和已封存报告不改写。
2. 主体角色和具体动作独立验证。无依据字段局部拒绝，提议值和拒绝原因留在受限观测审计，不成为事实账本字段。PR #96 的哈希、旧账本读取、证据撤回及幂等约束继续适用。
3. 同发行人、同市场的同阶段报道在发生时间等锚点充分时可合并；递表、聆讯等不同阶段保存不同 Event，通过现有观测 JSON 记录 `related_stage`。显式项目编号也不将不同阶段强制合成一个 Event。再次申请及收购进展有差异时保留为不同里程碑；弱关联不是已确认的同一申请过程。
4. 搜索任务保存 discovery/maintenance 意图、参考时间及窗口；查询、意图和窗口参与新缓存键。任务参考时间仅留作审计，不让相同请求因任务时间不同绕过有效缓存；新鲜度继续由既有 TTL 和读取时资格校验保证。仅使用已核验的共享名称；历史维护不贡献独立发现分子。保留现有硬预算和供应商适配，无新增付费能力。
5. 一篇文档可有多个事项、多个类别。文档取得、事项保留、主题检查和事实确认分别记录。已知模型次数耗尽保留规则结果，终结为 `status=failed`、`coverage.completion_status=partial`；这是复用既有终态避免继续认领，API 展示明确的部分结果。未知支出继续阻断派发。
6. HTML/PDF/专业正文保留有界片段和位置元数据。PDF 日期须有明确发布日期标记；请求失败保留派发次数、收到字节及异常阶段，不推断实际供应商费用。
7. 公司详情只在已授权请求内部批量加载证据、字段和支持关系；仍逐条检查许可、撤回、哈希和可见证据，不建立跨用户缓存。未确认事项继续隔离于已确认报告。

无新增表或迁移，head 保持 0035；算法版本升级会产生可审计的新版处理观测，不覆写原人工资料。旧代码可能忽略新增时间/关联/部分结果字段；若以后上线需回退，先停止新处理、保留追加历史和数据库备份，再验证旧读取行为，不能删观测或倒改历史迁移。

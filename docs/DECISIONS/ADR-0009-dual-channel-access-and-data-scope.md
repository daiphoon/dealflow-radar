# ADR-0009：个人与机构双通道访问及数据作用域

- 状态：已接受
- 日期：2026-07-16
- 决策范围：产品访问模型、数据作用域、权限契约和后续实施顺序

## 背景

当前 Demo 通过“用户 → 基金授权 → 投资关系 → 公司”验证基金私密字段隔离，因此没有基金授权的用户无法读取公司列表或详情。该路径适合机构投后闭环验证，但不适合作为“个人订阅 + 机构订阅”双收费模式的长期入口。

产品需要同时支持：

1. 个人用户直接搜索和跟踪未上市公司，不必创建基金、投资关系或关注列表；
2. 机构客户在平台共享公司档案之上管理基金、投资关系、内部资料和成员授权；
3. 同一自然人使用一个账户同时持有个人权益和一个或多个机构授权；
4. 同一工商主体原则上只建立一个全局公司 ID；
5. 已审核且许可允许复用的事实可以在平台客户之间共享，但未确认线索和客户私有资料不得跨所有者复用；
6. 平台共享不等于互联网匿名公开；第一阶段仍要求登录和有效访问资格；
7. 事件事实、证据引用和原始文档资产必须分别判断可见范围与使用许可。

本 ADR 扩展 ADR-0005 的公共事实与基金私密数据隔离原则，并澄清 ADR-0007 中事件状态和发布路由不能代替访问控制。它不修改 ADR-0008 的身份核验和“不自动创建未匹配公司”决定。

## 决定

### 1. 采用个人与机构双通道

#### 个人通道

个人用户未来可以：

- 按工商全称、统一社会信用代码或已核实别名搜索公司；
- 查看有权访问的平台共享公司档案；
- 将公司加入个人关注列表；
- 保存个人备注、查看水位和个人状态；
- 由个人订阅控制查询、关注、报告和刷新权益。

搜索和查看平台共享档案不要求先创建基金、投资关系或关注列表。关注列表只用于整理、变化跟踪和更新策略，不产生公司读取权限。

#### 机构通道

机构客户未来可以：

- 拥有一个或多个基金；
- 管理基金投资关系；
- 邀请员工、顾问或旗下投资人使用各自独立账户；
- 给成员授予机构、基金、组合或公司范围的访问权限；
- 在平台共享公司档案之上叠加机构私有投资数据、资料、备注和未确认线索。

基金是机构下的可选业务对象。`fund_access_grant` 只决定基金私有数据访问，不决定平台共享公司档案访问。

### 2. 术语和职责分离

| 术语 | 定义 | 不承担的职责 |
| --- | --- | --- |
| `user` | 一个自然人的全局登录身份；长期目标是一个人一个账户 | 不等同于机构、基金或订阅 |
| `organization` | 机构客户、机构资料和机构成员关系的业务所有者 | 不等同于基金，也不必直接对应付款交易 |
| `tenant` | 当前数据库和 RLS 使用的技术隔离边界；短期继续承载机构作用域 | 本阶段不物理改名，也不创建完整 organization 模型 |
| `fund` | 机构下的基金业务对象 | 不是平台共享档案的访问前置，默认不是订阅主体 |
| `investment` | 基金与公司之间的私有投资关系，可含金额、持股和内部估值 | 不进入平台共享公司快照 |
| `watchlist` | 个人用于整理和关注公司的清单 | 不授予公司读取权限，不表示投资关系 |
| `plan` | 套餐能力和限制的版本化配置 | 不保存用户资源授权 |
| `subscription` | 个人或机构获得某个 plan 的有效关系 | 不决定用户可访问哪个具体基金或私有资料 |
| `entitlement` | 订阅提供的能力或额度，例如查询、关注、报告、刷新和席位 | 不替代基金或资源授权 |
| `access_grant` | 用户对机构、基金、组合、公司或私有资料的具体访问授权 | 不表示付费状态或用量额度 |
| `usage_record` | 查询、关注、报告和刷新等产品权益的实际消耗记录 | 不记录 Provider 成本明细 |
| `usage_ledger` | Provider 调用、Token、延迟、估算费用和成本归因台账 | 不作为商业订阅的唯一用量账本 |

关注关系不得继续使用 `subscriptions` 命名；未来使用 `watchlists`、`watchlist_companies` 或等价名称，避免与商业订阅混淆。

### 3. 平台共享不是互联网匿名公开

数据作用域与访问资格是两个独立维度：

- **平台共享数据**：可以被多个有权限的平台客户复用，记录本身不归某个个人或机构独占；
- **订阅可见数据**：访问者必须登录，并具有有效个人权益或机构赞助权益；
- **互联网匿名公开数据**：无需登录即可访问，本阶段不作为默认目标。

新领域模型和文档使用 `platform_shared` 表示“平台内可复用”。现有数据库中的 `visibility_scope=public` 暂时保留为兼容名称，不在本 ADR 中修改；后续数据作用域 PR 决定是迁移为 `platform_shared`，还是在代码中建立明确映射。

采用 `platform_shared` 的理由是：`public` 容易同时被理解为“来源来自公开网页”“平台客户可共享”和“互联网匿名可访问”，三者的法律许可与访问控制并不相同。

### 4. 全局公司档案

1. 一个已核实工商主体原则上只有一个全局 `company_id`；个人、机构、基金、组合和关注列表都引用该 ID。
2. 统一社会信用代码是主要强标识；已核实工商全称、曾用名和其他已核实别名可以用于搜索。
3. 未核实主体、模糊品牌或无法唯一解析的简称不得直接进入平台共享公司目录。
4. 搜索无结果时创建“请求收录”或“研究请求”，不得根据模糊搜索自动创建或自动绑定公司。
5. 公司身份被确认不等于该公司的全部事件、文档和资料自动成为平台共享数据。
6. 共享公司搜索只返回允许进入共享目录的公司，不返回或统计个人、机构私有主体候选。

### 5. 数据作用域和所有权约束

至少支持以下作用域：

| 作用域 | 所有者要求 | 典型数据 |
| --- | --- | --- |
| `platform_shared` | 不得有个人或机构所有者 | 已核实公司身份、已审核共享事件、许可允许展示的证据引用 |
| `personal_private` | 必须且只能有 `owner_user_id` | 个人关注、备注、上传资料、查看历史、个人未确认线索 |
| `organization_private` | 必须且只能有 `owner_organization_id`；过渡期使用 `owner_tenant_id` | 基金投资、内部估值、机构资料、机构备注、机构未确认线索 |
| `system_restricted` | 无客户所有者或仅有系统归属，普通客户不可见 | 无法可靠回填所有者的历史记录、隔离数据、内部运行材料 |

每条可能包含私有内容的记录必须独立保存或可确定：

- `visibility_scope`；
- 所有者类型；
- 所有者 ID；
- 审核状态；
- 证据状态和许可状态。

数据库实现优先使用 `owner_user_id`、`owner_tenant_id` 或未来的 `owner_organization_id` 等显式外键和检查约束，不使用无法保证引用完整性的任意 `owner_type + owner_id` 多态键。

访问所有权与数据血缘分开保存。平台共享记录可以保留 `origin_user_id`、`origin_tenant_id`、导入批次和来源记录用于审计，但这些字段不是访问 owner，也不会使共享事实变为该来源客户私有。

必须满足以下不变量：

1. 平台共享记录没有个人或机构所有者；
2. 个人私有记录必须有且仅有一个个人所有者；
3. 机构私有记录必须有且仅有一个机构所有者；
4. 同一记录不能同时归个人和机构；
5. 未确认线索默认必须是个人私有、机构私有或系统受限，不能默认平台共享；
6. 私有记录不会因为另一用户关注或投资同一公司而自动共享；
7. `candidate`、`published`、`unconfirmed_lead` 等业务状态和发布路由不参与推断访问权限；
8. 私有记录的去重范围包含所有者，只有正式晋升后的共享事实才执行跨客户全局去重。

共享资格判定独立于事件业务状态。ADR-0007 允许自动发布的低风险例行事实，只有同时通过身份、来源许可、证据和共享作用域规则时才能进入平台共享层；`unconfirmed_lead` 必须经过有权限的明确审核和作用域晋升，不能因为同一公司被其他客户关注而自动共享。

### 6. 事件、证据引用和原始文档分别授权

事件事实、证据引用和原始文档资产是三个不同对象：

1. **事件事实**描述经审核的结构化结论，可以在许可和证据条件满足时晋升为 `platform_shared`。
2. **证据引用**描述来源名称、URL、日期、支撑关系和许可范围内的最小摘录；它有独立可见范围。
3. **原始文档资产**包括网页快照、全文、付费数据、附件和客户上传文件；它有独立访问、保留和再分发限制。

因此：

- 事件可共享不自动提升证据引用或原始文档的作用域；
- 来源可公开访问不等于平台有权复制全文、长期保存或转售；
- 平台共享事件默认只展示来源名称、URL、来源日期、检查状态和许可范围内的短摘录；
- 付费来源和许可受限内容继续按来源授权控制，不能因事件共享而向其他客户开放；
- 个人或机构上传资料不得因关联事件被晋升而一并共享；
- 如果私有或受限文档是唯一证据，且没有明确的事实复用权或可展示证据，事件不得晋升为平台共享；
- 一个共享事件可以保留受限证据关系供内部审计，但面向客户的响应只能返回其有权查看的证据元数据和摘录；
- 文档撤回、许可到期或证据失效时，应重新评估事件的共享资格，不静默保留无支持结论。

### 7. 公司详情按层组合

目标公司详情由两个逻辑层组成。

#### 平台共享基础层

- 已核验工商身份；
- 平台共享的已审核事件；
- 当前用户有权查看的证据引用；
- 数据新鲜度、最后检查时间和来源状态。

#### 私有叠加层

根据当前用户和所选访问上下文，可以叠加：

- 个人关注状态、个人备注和个人查看水位；
- 机构、基金或组合投资关系；
- 投资金额、持股比例和内部估值；
- 当前个人或机构所有的未确认线索；
- 当前用户有权查看的私有资料。

共享层先独立授权和读取，私有层再分别授权并拼装。没有基金授权但具有有效共享档案权益的用户仍可读取共享基础层。任何私有字段不得先进入共享缓存再依靠前端隐藏。

### 8. 权限公式和防枚举原则

目标权限公式为：

```text
平台共享档案读取 =
  已登录有效用户
  AND（有效个人权益 OR 任一有效机构赞助权益）

个人私有数据读取 =
  当前用户 ID = owner_user_id

机构私有数据读取 =
  有效机构成员关系
  AND 有效机构权益
  AND 有效资源授权
  AND 允许当前动作
```

补充规则：

- watchlist 只用于整理，不是公司查看权限；
- `fund_access_grant` 只控制基金私有层；
- 用户写入备注、上传资料或发起研究时必须具有明确的个人或机构上下文；
- 搜索只查询当前用户可访问的共享目录，不返回私有候选数量；
- 对不存在和无权访问的私有对象采用不可区分的响应；
- 字段缺失、结果总数、错误码、响应时间和缓存键不得泄露其他个人或机构的私有记录是否存在；
- 用户缺少通用共享目录权益时可以返回一致的权益错误，但错误不得暴露某个私有公司、基金或文档是否存在。

### 9. 机构赞助访问

1. 机构通过独立用户账户、机构成员关系和资源授权向员工、顾问或旗下投资人提供服务，不采用共享密码。
2. 机构可以按产品权益和资源授权限定用户可访问的基金、组合或公司范围。
3. 个人订阅与机构赞助权益可以同时存在于同一用户账户。
4. 平台共享功能的有效权益取个人权益和机构权益的并集；机构私有数据仍必须满足具体机构和资源授权。
5. 机构订阅失效时，机构提供的平台权益和机构私有数据访问失效。
6. 机构订阅失效不删除或转移用户的个人账户、个人关注、个人备注和个人订阅。
7. 机构数据继续归机构所有，不因成员离开或订阅失效复制到个人空间。

本阶段只定义模型，不开发支付、发票、分账、退款、结算或套餐扣费。

### 10. 迁移和兼容策略

1. 当前本地影子验证基金、基金授权和投资关系继续保留，不作为个人查询的前置条件。
2. 后续改造必须保持现有机构路径可用；平台共享层与基金私有叠加层分开后，现有基金用户仍能读取两层数据。
3. 当前两家真实公司“元素驱动（杭州）生物科技有限公司”和“毕诺济（上海）生物技术有限公司”是租户级记录。是否晋升为平台共享公司必须逐条人工确认身份、来源许可和共享范围。
4. 不批量把现有公司、已发布事件、候选事件、证据或原始文档设为平台共享。
5. 历史未确认线索优先根据导入批次和创建租户回填机构所有者；无法可靠确定所有者时进入 `system_restricted`，对所有普通客户不可见。
6. 历史原始文档的共享资格必须按许可单独回填，不能继承关联事件的作用域。
7. 所有结构变化通过新的 Alembic 迁移完成，不修改历史迁移。
8. 后续每个 PR 独立迁移、测试和回滚，不把用户身份、organization、订阅和支付重构塞入数据作用域 PR。

### 11. 后续实施顺序

#### PR 2：数据作用域安全基线

只处理：

- 未确认线索的个人或机构归属；
- 原始文档和证据引用的独立作用域；
- 所有者检查约束和保守回填；
- RLS、应用授权及跨用户、跨机构负向测试。

不开放个人搜索，不实现 watchlist、正式认证、subscription 或支付。

#### PR 3：平台共享公司搜索和详情 API

只处理：

- 信用代码精确搜索；
- 工商全称和已核实别名搜索；
- 按公司 ID 读取平台共享详情；
- 共享基础层与基金私有叠加层分离；
- 无基金用户在具备有效测试资格时读取共享档案；
- 搜索无结果时不自动创建公司；
- 同步请求不调用外部数据源。

#### PR 4：最小个人查询前端

只处理：

- 公司搜索框；
- 搜索结果；
- 平台共享公司详情；
- 有基金权限时叠加投资信息；
- 无权限时不返回也不显示私有字段。

完成 PR 2、3、4 后，再用 8—10 家真实公司同时验证个人和机构两条路径。个人 watchlist、备注、正式认证、订阅权益和支付系统分别在后续立项。

### 12. 测试契约

| 场景 | 必须满足的结果 |
| --- | --- |
| 1. 无基金用户搜索共享公司 | 返回其有权访问的共享公司，不要求投资关系 |
| 2. 无基金用户查看共享详情 | 返回共享基础层，HTTP 行为与有效资格一致 |
| 3. 无基金用户读取投资字段 | 金额、持股、内部估值不返回且不能由响应差异推断 |
| 4. 基金授权用户查看详情 | 返回同一共享基础层，并只叠加其获授权基金的私有数据 |
| 5. 用户 A 的个人未确认线索 | 用户 B 搜索、详情、计数和错误响应均不可见 |
| 6. 机构 A 的未确认线索 | 机构 B 的成员和服务身份均不可见 |
| 7. 两机构关联同一公司 | 共享事实使用同一公司和事件；投资、备注、线索和资料隔离 |
| 8. 同一用户拥有个人和机构权益 | 共享能力取并集；个人和机构私有数据按当前上下文分别授权 |
| 9. 机构授权或权益到期 | 机构赞助能力和私有数据访问失效；个人数据和个人权益保留 |
| 10. 私有原始文档关联共享事件 | 文档全文、快照和受限摘录不因事件共享而公开 |
| 11. 模糊搜索 | 不自动绑定、不自动创建公司，只允许请求收录或返回候选提示 |
| 12. 无权限请求 | 403、404、搜索数量、字段和时序不泄露私有记录存在性 |
| 13. 当前影子验证机构路径 | 现有基金、两家公司和授权投资叠加继续可用 |

## 方案选择

- 不采用“保留基金优先模型，只增加个人查询旁路”作为长期结构，因为它会保留两套互相分叉的授权逻辑。
- 近期采用“个人关注和查询通道与基金通道共存”的分步方案。
- 长期以全局用户、organization 成员关系、个人与机构订阅并存的双通道架构为目标。
- 不进行一次性 organization、正式认证、订阅和支付大重构。

## 影响

收益：

- 个人查询不再依赖虚构基金或投资关系；
- 已审核公共事实可复用，减少重复采集和重复公司档案；
- 基金与机构私密数据继续沿用现有隔离能力；
- 同一用户未来可组合个人和机构权益；
- 原始文档许可不会被事件共享状态覆盖。

代价和风险：

- 事件、证据引用和原始文档需要独立作用域与回填；
- 现有 `public` 术语和租户级真实公司需要保守迁移；
- 搜索、错误处理、缓存和详情拼装都要增加防枚举测试；
- 正式认证和商业权益未实现前，只能在受控测试环境验证目标访问模型。

## 暂缓决定和 Open Questions

以下问题不阻塞本 ADR，也不得在 PR 2、3、4 中擅自扩展：

1. 机构赞助用户默认可搜索整个共享目录，还是只可搜索机构授予的公司范围；由未来 plan/entitlement 设计决定。
2. 数据库枚举是否从 `public` 迁移为 `platform_shared`，还是保留旧值并在领域层映射；由 PR 2 在兼容性评估后决定。
3. 各类来源允许保存的摘录长度、快照期限和再分发范围；需要来源许可矩阵和运营主体合规确认。
4. 当前两家真实公司何时及是否晋升为平台共享公司；必须在后续数据审查中逐条决定。
5. organization 是否最终物理替换 `tenants` 表名；在完整机构模型立项前不决定。

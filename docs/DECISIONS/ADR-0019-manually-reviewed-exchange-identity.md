# ADR-0019：交易所披露资料的受控人工主体核验

- 状态：已确认；代码交付与生产启用分别验收。
- 范围：补充 ADR-0008 的身份依据；不恢复 ADR-0018 已退役的商业数据路线。

## 背景与决定

真实验收遇到登记机关公开页面缺少信用代码、交易所正式披露文件却能提供同一主体完整身份字段的情况。不能把交易所文件伪称为政府工商证据，也不能跳过身份闸门直接研究。

复用现有 `OfficialIdentityProvider`、私有 JSON 导入、`official_identity_verifications` 和身份工作台，新增独立依据 `exchange_disclosure`。这表示“交易所披露资料经平台管理员人工核验”，不是政府登记机关实时查询，也不是交易所对所有业务事实作保证。公司详情显示“已核验（交易所披露·人工核验）”。

## 最小准入契约

1. 首版仅接收 HTTPS 的 `hkexnews.hk`、`www.hkexnews.hk`、`www1.hkexnews.hk` 正式披露 PDF，路径限制为 `/listedco/listconews/sehk/`；不支持任意网站、非标准端口、查询参数或路径绕行。不新增下载器、搜索接口或新 Provider。
2. 操作者必须是 active 用户，同时具有有效的 `institution_admin` 和 `platform_admin`。冲突候选在原身份工作台选择时，还需原有的 `reviewer` 角色；不扩大跨租户读取范围。
3. 管理员应亲自核对文件发行主体、当前工商全称、信用代码和注册地区确实属于同一主体；不得把品牌、子公司、另一文件字段或推测拼成证据。输入 `identity_fields_confirmed=true`、`review_reason`、最小 `evidence_excerpt` 和 `evidence_locator`（页码/章节）。程序校验代码校验位、摘录中的代码、必填字段和 URL；人工确认不等于程序已理解 PDF。
4. `data_updated_at` 记录该披露文件的资料基准/披露日期，`checked_at` 为人工核对时间，`queried_at` 为资料整理时间；必须依次不晚于后者。不能用今日核对时间伪造资料更新日期；登记状态只照资料记录，未披露则保持未知，不声称已取得当前工商存续证明。
5. 仅匹配当前可访问的既有公司。代码、名称或注册地冲突不得静默覆盖；保留私有冲突候选，经工作台留理由处理。未匹配到公司时只保存核验记录，不自动建公司、不自动排研究任务。
6. 身份通过不等于目录准入、研究授权或事件发布。原有共享目录、管理员批准请求、研究预算、单任务临时开关和自动发布关闭规则全部保留。已上市例外技术样本不得计为未上市公司独立用户验收成功。

## 血缘与权限

- 保留文件哈希、批次、原始记录、来源、核验结果/规则和时间；原有文件哈希与批次幂等规则不变。
- 原始记录保存到本租户 `organization_private` 文档，新增人工审计片段包含实际操作者、实际记录时间、理由、依据及策略版本 `exchange-identity-v1`。`ResearchImport.imported_by` 保留导入操作者，不接受输入覆盖系统审计字段。
- 共享公司只显示核验依据，不公开私有摘录、页码底稿、审核上下文或原始文件；RLS 规则保持不变。
- 现有 `license_status=public` 只表示该身份资料公开可获取，不推定全文保存、商业再分发或共享事件许可。身份导入只保存最小字段及摘录，不下载、复制或发布 PDF；真实 JSON/PDF 底稿留在 Git 忽略的私有目录。

## 迁移、回滚与验收

- 新迁移 `0026` 只扩展公司和核验表的两项依据约束，不修改历史迁移、既有身份、共享状态、基金关系或 RLS；历史 `licensed_business_data` 仅保留审计兼容，不新增入口。
- 合并后方可另行备份、升级、部署和真实导入。本 PR 不修改生产数据或开启研究/模型。
- 无新依据数据时可 `0026 → 0025`；任一表存在 `exchange_disclosure` 时降级必须明确拒绝，不删数据或改称政府来源。优先回退应用版本并保留向前兼容数据库；旧版本无法完整呈现新依据，需先在隔离备份验证。
- 验收覆盖政府路径回归、新来源字段与域名拒绝、平台角色/失效角色、重复导入、主体冲突、工作台选择与重路由、私有证据隔离、原申请批准后排队、SQLite/PostgreSQL 迁移和真实 PostgreSQL RLS。所有测试使用虚构资料，外部业务调用与模型 Token 为 0。

## 非目标与后续闸门

不开发通用交易所适配器、PDF 自动抽取、主体自动建档、自动晋升、研究扩题或大模型。当前先交付未合并代码 PR；审查通过后，按备份 → `0026` → 部署 → 原请求人工核验/批准 → 原预算单任务验证推进。没有新的未决产品方向；真实文件是否满足本契约仍需逐份确认。

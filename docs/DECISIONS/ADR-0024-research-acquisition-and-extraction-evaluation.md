# ADR-0024：先验证专业获取与受限抽取，再完成研究链路改造

- 状态：2026-09-22 负责人批准调整后的执行顺序；结果以有效看板为准。
- 补充 ADR-0021/0023，保留人工初始库、后台更新、证据和权限边界。

## 决定

1. E4.8 先分别测量搜索发现、正文取得与事项理解，随后按证据完成适用的局部重构；不再仅围绕网页排序修补。Tavily 是待验证通道，当前不全量替换百度/博查。
2. 输入在调用前冻结：相同的无答案查询分别交给各搜索 Provider；相同的已知 URL 分别交给现有抓取器与 Tavily Extract。已知 URL、原表答案和维护材料命中不得计入独立发现。原 E4.7 的 3/9 保留。
3. 用封存正文比较当前规则与受限模型抽取；只发送必要公开摘录及已确认名称，不传私有投资数据。模型无工具、无自主搜索、无发布权限。字段须关联逐字原文；原文位置有效不等于语义正确，主体、资金方向、IPO 阶段和归并须独立评分。未知日期不推算。
4. 评估工具默认 dry-run，不连接业务数据库。调用前记录清单哈希、预算预留和开始状态；中断/未知支出不自动重跑，失败保留。测试使用 Mock，真实结果留在私有忽略目录。
5. 本次固定 5 家已知回归样本：三家搜索各 10 次、8 个固定网址双通道读取、13 份正文抽取；Tavily 最多 100 credits，现有搜索各 10 次免费调用，直接 HTTP 最多 32 次，DeepSeek 总费用最多 1 元。实际清单预留低于上限；生产预算不变，无需充值或开启自动付费。
6. 先完成对照和结果审查，再选取确有收益的获取/抽取能力进入 E4.8 工程。保留 Provider 抽象，不同时接入多个尚未比较的新服务。正式新留出样本在工程稳定后单独冻结，不能把已看过的五家继续称为盲测。合并、部署与长期自动更新启用仍分别记录授权和验收。

## 验收

- 分别报告检索线索、可用正文、原文支持字段、事项归并及最终交付，不将调用成功当业务通过。
- 报告每条有效事件的成本、耗时、失败类型、重复和主体错误；技术失败单列，不删除不利样本。
- 保留响应/必要摘录的来源和哈希，禁止将供应商生成答案冒充原文。
- 新通道通过原文、语义、幂等、预算及权限验证后才能进入业务流程；效果不佳时保留已有资料，按具体失败调整，不自动追加无界研究。


## 2026-09-22 已批准的工程选择

- 保留百度/博查；Tavily 作为可选搜索 Provider 和按明确域名配置的正文获取通道。先复用有效搜索缓存中的 `raw_content`，否则才调用 Extract；搜索摘要和供应商生成答案不作为正文。原站 HTTP 状态未检查时保持未知，专业获取不用于重试已明确受限的来源。新通道默认关闭，不扩大原 4 搜索/8 网页/2 MB/180 秒上限。
- `matter-v1` 将单篇材料拆为有主体口径、子类型、动作状态和字段原文的事项，八类共用存储/证据/展示契约。融资细分资金流向及注册资本/估值/股份数量；IPO 分辅导协议、备案、辅导完成、受理、问询、聆讯、发行和实际上市。规则不能识别的动作不凭模型命名成为事实；品牌不升级为法人。
- 模型只提议逐字动作和字段，最终受确定性类型、原文和语境校验；单字段失败独立剔除，保留其他有依据字段。默认关闭，模型名称/价格由配置提供；默认每任务最多 3 次、每次输入保守上界 16,000、输出 2,000 tokens，无自动重试。输入过长使用规则并保留底稿；未知支出停止待核对。24 是单次模型响应的条目结构上限，不是人工导入或公司总资料上限。
- 复用现有 `event_observations` 和证据表，以主体、阶段、轮次/金额/明确投资方以及日期约束比对已有事项；冲突追加观测，不覆盖人工事实。缺日期材料只能维护可唯一识别的已有事项，不能生成近期新事件或刷新新鲜度。来源撤回不删除内部幂等历史，也不恢复展示。
- 新迁移 `0034` 只增加八类 `matter-v1` 观测的管理员读/追加策略；普通用户仍不能读受限正文或内部观测。已有数据时拒绝降级删除策略。回滚先关闭新路径；有新事项后须保留其读取与撤证兼容，不直接回到不识别新格式的应用版本。
- 工程验证先用 Mock、隔离数据库和原封存材料，真实调用与生产写入为零。新提示词效果和实际召回尚需下一次预先冻结的新留出样本；这次回归不能改写原 E4.7 的 3/9，也不能证明其余六类的真实覆盖。

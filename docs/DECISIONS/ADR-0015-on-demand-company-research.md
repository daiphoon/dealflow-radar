# ADR-0015：新公司按需研究、共享缓存与分级事实展示

- 状态：已接受，分两步实施
- 日期：2026-08-26
- 关联：ADR-0001、ADR-0004、ADR-0007、ADR-0009、ADR-0010、ADR-0011

## 背景

邀请测试已经证明公司查询、个人与机构权限、共享事实、证据和报告的技术路径可用，但数据库覆盖仍小。继续人工逐家公司补内容不能形成可扩展产品；在用户打开查询页时同步等待天眼查或模型，又会把供应商超时、额度耗尽和网络失败直接传给网页。

项目需要把“查询已有数据库”和“后台研究新公司”分开：网页先返回已有结果；数据库没有目标公司时，用户提交准确工商全称或统一社会信用代码，后台任务完成身份核验和后续研究。任务状态保存在 PostgreSQL，因此退出登录、关闭页面或断线不会中断任务。

## 决策

### 1. 查询与研究分离

1. 同步公司搜索和详情只读取 PostgreSQL，不调用天眼查、搜索服务或大模型。
2. 本地共享目录有结果时，用户直接读取缓存；数据过期时复用现有结果并按规则创建或合并后台任务。
3. 本地没有结果时，不调用外部接口生成联想候选。页面要求用户输入准确工商全称或 18 位统一社会信用代码，信用代码优先。
4. 后台先核验工商身份，向用户展示工商全称、信用代码、地区和登记状态；用户确认主体后才开始完整研究，避免研究错公司。
5. 一个已核验工商主体继续只使用一个全局 `company_id`。不同个人、机构和基金的相同公司研究请求复用同一活动任务和可共享结果，基金不拥有或锁定公司主档。

### 2. 个人额度、平台额度与排队

1. 每位用户默认最多发起 10 家新公司研究/天、30 家/月；同一公司 24 小时内重复提交复用原请求，不重复创建任务。
2. 用户可在页面申请临时增加日额度或月额度，由平台管理员决定增加量和有效期；不得由前端自行提高。
3. 天眼查正式 VIP 的供应商合同额度按 1000 次/天、10000 次/月建模。系统保留 10% 安全余量，因此自动任务默认最多使用 900 次/天、9000 次/月；保留额度用于失败重试、人工复核和突发运营。
4. 个人提交额度与供应商调用额度相互独立。达到任一闸门时任务进入 `budget_deferred`，保留排队位置和已有结果，不切换到更昂贵服务。
5. 有效私有缓存必须在供应商预算闸门之前查询；完整缓存命中时即使当日或当月外部额度已耗尽，也可以零外部调用复用。只有缓存不完整时才检查并预留外部调用预算。
6. 首版只运行一个按需研究 Worker，以 PostgreSQL 租约、幂等键和活动任务唯一约束防止重复执行；同一 Worker 进程内复用一个 Provider 实例，使相邻任务之间也遵守供应商最小请求间隔。引入原子预算预留前禁止启动多 Worker 或水平扩容；不引入 Redis、Celery 或通用分布式队列。

### 3. 取消、断线和部分结果

1. 排队中的请求可立即取消；正在执行外部调用时记录取消请求，完成当前调用后停止下一步，不能通过断开网络强行中止正在传输的请求。
2. 已经取得且通过结构校验的资料保留在平台缓存，不因用户取消而删除；后续用户查询同一公司可以复用，避免重复付费和调用。
3. 用户日提交次数不因取消退还，防止通过反复提交和取消消耗资源。若取消前外部调用为 0，可退还本月新公司额度；一旦发生外部调用，本月额度不退还。
4. 取消后同一用户对同一公司仍有 24 小时冷却期。异常高频取消进入运营审计，但不自动影响其他正常用户。
5. 任务、阶段、已完成覆盖、调用次数、缓存命中、错误、租约和更新时间均持久化。用户重新登录后看到同一状态和最新结果。
6. 个人取消只修改本人申请，不直接修改全局公司研究任务。平台 Worker 在受限服务身份下协调：仍有其他活动申请时继续全局任务，已无任何活动申请时才取消排队任务或请求运行中任务停在当前外部调用之后。

### 3.1 客户状态与运营诊断分离

1. 个人接口只返回客户理解任务所需的阶段、时间和通用提示；不返回精确外部调用数、缓存命中数或“命中其他客户私有公司”等内部原因。
2. 平台管理员可在受权运营端查看精确调用、缓存和私有档案冲突原因；该诊断数据不是个人产品权益。
3. Worker 每次 `commit` 或 `rollback` 后必须重新设置 PostgreSQL 事务级 RLS 请求上下文，不得依赖上一事务的会话状态。

### 4. 首次研究覆盖与成本顺序

首次完整研究按天眼查当前六大数据模块组织调用：工商基础、风险、知识产权、经营、历史变更和董监高/人员。公司实体锚定是进入六大模块前的独立步骤，不计作第七个研究模块。

系统现有八类事件——财务与经营、融资与股权、合同与商业进展、产品与技术、治理与人员、司法与合规、产能与资产、退出与流动性——是研究结果入库后的产品分类，不是八组固定外部查询。一个数据模块可以映射到多个事件分类，一个事件也可以组合多个模块或其他可信来源；不得为了填满八类而额外调用没有证据价值的接口。

执行顺序遵循“先结构化、后内容；先缓存、后外部；有变化才处理”：

1. 复用有效缓存、现有原始记录和同公司活动任务；
2. 调用天眼查的必要结构化工具，按模块记录是否已覆盖；
3. 去重后只处理新增或变化记录；
4. 只有需要分类、结构化提取或谨慎摘要的新增内容才调用模型；
5. 用户未明确点击“生成报告”时不调用模型生成完整报告。

现有固定 10 家公司只作为已经完成的展示测试样本，不再为追求内容穷尽度发起外部查询。首轮真实联网验收只选择一家具备准确身份、此前未进入数据库的新公司。

### 5. 事实、线索和来源边界

1. 天眼查返回且通过 Schema、信用代码、主体和幂等校验的结构化原始记录，可以标记为“来源记录已核验”；这不等于平台对原因、责任、经营好坏或投资风险作出结论。
2. 可确定、低风险的结构化例行事实可以依据版本化规则形成平台共享事实；事实必须保留来源、查询时间、字段映射、策略版本和证据引用。
3. 需要人工判断的记录不等待管理员才让请求用户看到，可先以醒目的“待核实线索”展示，并说明尚未构成平台核实结论；随后进入人工队列。
4. 该“平台研究线索”只来自平台主动调用且授权明确的来源，可以在同一全局公司后续查询中复用。个人上传、机构上传、个人私有线索和机构私有线索仍按 ADR-0009 隔离，不因本决策跨客户共享。
5. 严重负面、主体冲突、来源冲突、证据不足和模型推断不得自动升级为已核实事实。即使天眼查返回了诉讼、处罚等结构化条目，也只能自动确认“来源返回了该条记录”，不能自动推导欺诈、经营恶化或持续经营结论。
6. `AUTO_PUBLISH_ENABLED=false` 继续保持。按版本化规则自动展示例行结构化事实与“自动发布任意生成结论”是两件不同的事；任何实现不得借此恢复无闸门发布。
7. 事件事实、证据引用和原始响应分别决定作用域。授权原始响应保存在受限缓存；客户页面只展示许可范围内的结构化字段、来源引用和必要摘录。

### 6. 会员开通和批量能力

1. 当前未开通正式 VIP，不因开发自动购买或接受服务。代码、配置示例和测试直接按正式 VIP 上限实现，避免开通后再改业务逻辑。
2. 开发、迁移、Mock 测试和部署均保持真实调用关闭。只有两个代码 PR 合并、香港环境升级完成并准备使用一家具名新公司做最终实测时，才提醒项目负责人开通 VIP。
3. 当前不实施离线批量导出、批量建库或全量预热。未来基金客户合法提供一批公司清单且批量运营的收益超过成本时，再独立立项；不得把网页 VIP 导出能力混入实时查询队列。

## 分阶段交付

### PR 1：身份确认、额度、队列、取消和恢复

- 新增保守数据库迁移，扩展个人请求状态，增加全局公司研究任务、临时额度申请、租约、取消和调用计数；
- 增加用户确认身份、取消请求、查看排队与申请临时额度的 API 和最小页面；
- 增加后台身份核验 Worker，只有专用开关显式开启时才允许调用；
- 完整缓存先于外部预算闸门；个人状态与平台诊断分离，个人取消由 Worker 协调到全局任务；
- 信用代码/工商全称输入、身份候选、任务状态和部分结果均可持久恢复；
- 自动测试不调用真实天眼查，生产部署在 PR 2 和最终真实验收前保持 Worker 外部调用关闭。

### PR 2：六大模块研究、去重缓存和分级展示

- 按六大模块覆盖表先调用高信息密度总览，只有发现新增、变化或不确定项时才下钻必要明细；保存每阶段状态、调用量、缓存命中和部分结果；
- 同公司任务合并、内容哈希和来源 ID 去重，取消后保留可复用结果；
- 区分“已核实事实”“待核实线索”和“无可靠公开数据”，个人页面不得混淆；
- 只对新增内容执行必要模型步骤，报告继续由用户显式申请；
- 完成个人/机构/RLS、取消恢复、额度、缓存、异常和浏览器端到端验收。

## 验收和启用闸门

1. 两个 PR 的迁移、RLS、后端、前端、CI 和浏览器 Mock 验收全部通过；
2. 搜索和详情同步请求的外部调用保持 0；
3. 身份未确认、错公司、冲突主体、额度耗尽、取消和断线均不会产生错误共享事实；
4. 同公司重复请求复用活动任务，缓存期内不重复调用；
5. 个人和机构私有数据不进入共享结果；
6. 现有 10 家测试公司没有新增外部调用；
7. 项目负责人开通 VIP 后，只用一家具名新公司做一次受控真实验收，核对天眼查调用量、模型 Token、结果覆盖、页面状态和取消恢复；
8. 真实验收通过前，香港环境不得面向测试用户开放新公司外部研究能力。

## 非目标

- 不做外部公司名称联想、错别字或模糊主体自动绑定；
- 不做离线批量建库、每日全量扫描或现有 10 家内容穷尽；
- 不自动生成报告；
- 不接入新的付费 Provider；
- 不恢复严重负面自动发布；
- 不实现支付、正式套餐、organization 重构或分布式爬虫。

# ADR-0014：邀请测试先部署腾讯云中国香港，企业化后再评估迁入大陆

- 状态：已接受
- 日期：2026-08-11
- 取代：ADR-0013 中“上海服务器 + 个人备案”的短期部署路线
- 保留：ADR-0013 的单机 Compose、PostgreSQL 内网隔离、客户端加密异机备份和应用优先回滚原则
- 关联：ADR-0005、ADR-0009、ADR-0012、ADR-0013

## 背景

M5A 和 M5B 前置已经验证可迁移的生产镜像、Caddy 单一入口、同机 PostgreSQL、受限应用账户、RLS、配置预检以及 `age` 加密备份和恢复工具。原计划购买上海服务器并以个人主体备案，但当前产品属于企业信息查询与持续跟踪服务，个人备案路径存在内容和后续经营主体不匹配风险。

项目负责人决定先购买腾讯云中国香港服务器，面向 5—10 名受邀测试用户形成公网 MVP；验证产品价值和运营流程后，再成立公司并决定是否迁入中国大陆、办理企业 ICP 备案和开展正式收费。腾讯云当前说明，中国香港服务器不需要 ICP 备案，也不能作为大陆备案资源；使用中国大陆资源对外提供服务时仍须先备案。[是否需要备案](https://cloud.tencent.com/document/api/243/19630)、[备案云资源](https://cloud.tencent.com/document/product/243/18908)

## 决策

1. M5B 的当前目标环境为腾讯云中国香港云服务器。起步容量以单机 2 核 4GB、80GB 以上磁盘作为购买比较基线，实际套餐、带宽、期限和价格必须在购买前由项目负责人确认，不写死在代码或文档中。
2. 复用现有 Docker Compose：FastAPI、Next.js、Caddy 和 PostgreSQL 同机部署。PostgreSQL 只加入内部容器网络，不发布 `5432`；API 和前端端口不直接暴露，公网只允许 Caddy 的 `80/443`。
3. 客户通过 `https://app.dealflowradar.cn` 访问，不使用 Tailscale。服务器管理优先使用 Tailscale SSH；云安全组不向全网开放 SSH、数据库、`3000` 或 `8000`。未备案域名不接入中国大陆 CDN。
4. CloudBase 继续只负责身份认证。现有环境、邮箱账户和稳定 subject 可以复用；PostgreSQL、tenant、基金、角色、RLS 和业务数据不迁入 CloudBase。域名切换后允许用户重新登录一次，不为迁移复制浏览器 Cookie。
5. MVP 保持邀请制，不提供匿名注册、支付、公开营销或生产级 SLA。初始数据只使用许可明确的平台共享公开信息、虚构投资数据和必要的测试账户资料；未经明确授权，不上传真实基金敏感文件、投资金额、持股、内部估值或未公开材料。
6. 部署时以下能力必须保持关闭：`EXTERNAL_CALLS_ENABLED`、`PAID_API_CALLS_ENABLED`、`AUTO_REFRESH_ENABLED`、`AUTO_PUBLISH_ENABLED`、`TRUSTED_SOURCE_CALLS_ENABLED`、`SOURCE_MONITOR_SCHEDULER_ENABLED` 和 `REVIEW_WORKBENCH_ENABLED`。旧商业数据身份专用开关已由 R1 删除。后续单项开放仍需独立许可、预算和验收，不因服务器上线自动开启。
7. PostgreSQL 备份继续先使用离线保管私钥对应的 `age` 公钥完成客户端加密，再上传到独立的私有 COS 存储桶。生产主机不保存解密私钥；保留 14 个每日和 8 个每周恢复点，必须完成从 COS 下载到隔离数据库的真实恢复。
8. 香港环境属于跨境部署。邀请前必须提供最小隐私与测试说明，明确服务地区、收集字段、用途、保存期限、退出和纠错方式；坚持数据最小化，不把“测试用户较少”当作免除安全或隐私责任的理由。
9. 家庭服务器 `ruitian100` 不承载本项目。其 OpenClaw 和其他工作负载的维护与本产品部署分开，不共享端口、数据、Secret、备份或运维变更。

## M5B 验收闸门

以下条件全部满足后，才可开始 M6 的 5—10 人邀请测试：

1. 固定提交对应的不可变镜像可在干净香港主机部署，生产配置预检通过；
2. 云安全组和主机防火墙只开放必要入口，公网扫描确认 `5432/3000/8000/SSH` 不直接暴露；
3. 域名和真实 HTTPS 正常，安全响应头、证书续期和 CloudBase 安全来源配置已验证；
4. 数据库迁移、非表所有者 `NOBYPASSRLS` 应用账户、两个租户负向权限测试通过；
5. 个人、基金用户、其他租户用户和平台管理员四类真实 CloudBase 账户完成浏览器回归；
6. 加密备份、COS 上传、保留规则、异机下载和隔离恢复通过，源库与恢复库版本及关键数量一致；
7. 主机重启后自动恢复，`/health`、`/ready`、磁盘、证书、服务和备份失败告警可观测；
8. 至少完成中国大陆两种不同运营商网络的登录、查询和公司详情冒烟，记录延迟和失败但不为通过而隐藏网络问题；
9. 外部业务调用、付费调用、模型 Token、自动刷新和自动发布均为 0；
10. 已有本地影子基金、平台共享事实晋升/拒绝/撤回和个人核心路径无回归。

## 未来迁入中国大陆

香港 MVP 运营结果达到 M6 预先确认的价值和安全门槛后，才启动大陆迁移决策。至少需要：

- 成立并确认实际经营主体；
- 购买符合备案条件的中国大陆云资源并完成企业 ICP 备案；
- 复核企业信息查询、收费模式、隐私、数据来源展示和必要许可；
- 在新环境先完成备份恢复、权限和浏览器验收，再降低 DNS TTL 并切换流量；
- CloudBase 身份可以继续使用，但本地身份映射和审计必须随 PostgreSQL 完整迁移；用户在新域名或会话失效时重新登录；
- 切换稳定后按保留策略删除香港主机和临时副本，保留必要审计和加密备份；
- 应用回滚优先切回已验证镜像并保留向前兼容数据库，不直接执行生产数据库 downgrade。

## 非目标与限制

- 本决策不授权自动购买服务器、开通 COS、修改 DNS、接受付费条款或创建云资源；这些动作仍需项目负责人确认实际商品和价格。
- 本阶段不开发支付、正式订阅、公开注册、organization 重构、自动采集、自动发布或高可用集群。
- 香港单机仍是单点故障，不承诺正式 SLA；MVP 成功不自动等于可以收费或公开推广。
- 香港访问中国大陆的网络质量必须实测，不能以地域接近推断稳定性。

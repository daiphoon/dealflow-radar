# ADR-0001：按需更新加低频巡检

- 状态：已接受
- 日期：2026-07-13

## 背景

Demo 用户少、预算低，未上市公司多数日期没有新公开信息。每日全量更新会让任务数接近 `30N`，产生大量无变化搜索和审核噪声；纯定时分级仍会扫描无人关注公司。

## 决定

采用 `next_check_at` 驱动的按需更新加低频巡检：查询过期数据时先返回旧快照，再经预算、TTL、冷却和幂等检查入队；关注、近期事件和高风险公司临时升频，长期无变化降频。无新内容不调用 LLM、不重建报告。

成本比较使用 `T→S→L→C` 可调公式和实际用量台账，不把供应商价格写进业务逻辑。规划情景见[成本控制](../06-cost-control.md)。

## 影响

优点是显著减少无变化任务、提升缓存命中和每条有效事件效率；代价是低关注公司发现延迟更长，必须准确展示新鲜度和信息缺口。若未来合同要求全组合时效，再基于实测成本评估分级定时或更高频策略。

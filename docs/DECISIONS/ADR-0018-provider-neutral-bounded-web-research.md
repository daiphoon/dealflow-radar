# ADR-0018：供应商中立的受限公开网络研究

- 状态：已接受，待分阶段实现
- 日期：2026-09-02
- 取代：ADR-0010
- 部分取代：ADR-0015、ADR-0016
- 保留并遵循：ADR-0001、ADR-0002、ADR-0004、ADR-0007、ADR-0009、ADR-0011、ADR-0017

> 2026-09-13 部分更新：[ADR-0022](ADR-0022-curated-baseline-and-incremental-research.md) 允许负责人明确确认的资料经轻量校验准入，第 1 节不再要求此类资料重复公开交叉查证。供应商独立、后台研究、预算及证据边界保留。

## 背景

现有系统已经具备公司身份闸门、PostgreSQL 后台任务、取消与断线恢复、可信来源抓取、原始证据和哈希、结构化事件、共享/私有作用域、证据约束模型解读及完整审计。此前的按需研究把天眼查作为工商身份和六大模块数据入口，能够完成小样本验证，但其可用额度和商业可持续性已不能支持产品后续路线。

若继续把生产队列、页面进度和研究结构绑定在单一供应商上，会形成新的供应商锁定；若直接引入可以自由选择工具、反复搜索和自行发布结果的通用 Agent，又会放大费用失控、主体误配、来源不可追溯和严重负面误发布的风险。

因此，本决策保留现有可复用底座，将数据发现改为供应商中立、预算受限、证据优先的公开网络研究流程。天眼查现存实现进入单独的安全退役阶段，不作为新功能的前置依赖。

## 决策

### 1. 身份先于研究

1. 新公司研究继续要求准确工商全称和统一社会信用代码。
2. 公司身份必须通过现有身份核验流程确认后，才能进入公开网络研究。
3. 模糊网络结果、品牌名、简称或模型判断不得自动创建公司、改写信用代码或确认工商主体。
4. 身份歧义时停止自动绑定，保留候选并进入现有人工消歧流程。

### 2. 同步页面不等待外部调用

1. 公司搜索和详情请求只读取 PostgreSQL 中已有结果。
2. 数据缺失或过期时，先返回最近一次结果和新鲜度，再按预算、冷却期和去重规则创建后台任务。
3. 用户断线或退出登录不终止后台任务；重新登录后可按任务 ID 恢复进度。
4. 用户取消后不再开始新的外部步骤；已取得且通过身份、许可和证据校验的中间结果可以进入共享缓存，未验证结果不得发布。

### 3. V1 继续使用 PostgreSQL 任务状态机

V1 复用现有 `refresh_jobs`、租约、心跳、幂等、检查点和用量台账，不引入 Pi、LangGraph、Deep Agents、Celery、Redis 或第二套 Agent 状态存储。

只有真实运行证明现有任务表无法表达必要的暂停、恢复或并发能力时，才通过新的 ADR 评估替换运行时。避免同时维护“业务任务状态”和“Agent 图状态”两套真相来源。

### 4. 采用受限研究循环，而非自主无限循环

单次研究任务按以下固定阶段执行：

```text
已核验公司
  → 新鲜度、缓存和预算检查
  → 固定投资研究计划
  → 受限搜索
  → 来源筛选和安全抓取
  → 原始证据、哈希和许可记录
  → 确定性解析、去重和差异识别
  → 必要时模型结构化抽取与重要性解读
  → 主体、数字、日期、证据和作用域校验
  → 已核实事实或待核实线索
  → 页面读取数据库结果
```

每次任务必须配置并强制执行：

- 最大搜索次数；
- 最大补充研究轮数；
- 最大候选 URL 和抓取文档数；
- 单页和任务总下载字节；
- 单次及累计超时；
- 模型输入和输出 Token；
- 外部调用及模型费用；
- 同公司冷却期和平台并发上限。

达到任一上限即保存检查点并停止，不自动扩大范围、不切换到更昂贵 Provider，也不把“研究未完成”改写为“未发现风险”。

### 5. 先执行固定研究维度，再做有限补缺

首轮围绕投资者真正关心的变化组织查询，而不是为了填满字段穷尽网页：

1. 财务与经营；
2. 融资与股权；
3. 合同与商业进展；
4. 产品与技术；
5. 治理与核心人员；
6. 司法与合规；
7. 产能与资产；
8. 退出与流动性；
9. 信息质量和关键缺口。

首轮后只允许对明确的高价值缺口进行有限补充搜索。没有新证据时，不调用模型、不重写快照、不生成完整报告。

### 6. Provider 中立边界

业务编排只依赖版本化协议：

- `SearchProvider`：发现标题、URL、摘要、发布时间和来源记录 ID；
- `DocumentFetcher`：在域名、robots.txt、SSRF、重定向、MIME、字节和超时约束下取得允许的内容；
- `StructuredDataProvider`：未来接入取得明确许可的结构化数据；
- `LLMProvider`：对已取得的最小必要证据片段做严格 Schema 输出；
- `JobQueueProvider`：V1 映射 PostgreSQL 任务表。

Provider 由配置和依赖注入选择，业务代码不得直接依赖供应商 SDK、返回字段或配额名称。搜索 Provider 的正式选择不在本 ADR 中完成，必须经过单独的准入与真实样本验证。

### 7. 搜索结果不是证据

搜索摘要只用于发现候选页面，不得直接作为已核实事实。事实必须引用实际打开、许可允许且主体匹配的页面或正式结构化来源。

抓取继续复用现有可信来源安全边界：阻断私网、回环、链路本地、元数据地址、非允许协议、危险重定向、超大响应和非预期二进制；遵守 robots.txt，不登录、不提交表单、不绕过验证码、付费墙或反自动化措施。

许可不明确时只保存 URL、标题、日期、哈希和最小定位信息，不长期保存全文，也不直接向订阅用户展示受限内容。

### 8. 确定性处理优先，模型只处理增量证据

1. URL 规范化、内容哈希、日期解析、已知字段映射和精确去重优先使用程序规则。
2. 只有新文档或内容变化、规则判定相关且预算通过时才调用模型。
3. 模型输入只包含必要公司身份、标题、来源、最小证据片段和输出 Schema。
4. 模型输出必须通过 JSON Schema、公司身份、证据引用、数字、日期、前后值和禁语校验。
5. 校验失败最多修复重试一次；仍失败则保留失败记录，不进入正式事实。

### 9. Agent 工具白名单与禁止能力

受限研究 Agent 只允许：

- 搜索已核验公司的公开资料；
- 抓取通过安全检查的候选 URL；
- 读取已有平台共享事实和可用证据元数据；
- 提交结构化候选、研究缺口和运行检查点。

Agent 不得：

- 执行 Shell、任意 SQL 或任意文件系统操作；
- 访问未通过安全策略的任意网络地址；
- 创建或确认公司身份；
- 读取个人或机构私有投资数据作为共享研究输入；
- 直接改写、发布、撤回或删除共享事实；
- 修改额度、安全开关、权限或 Provider 配置；
- 因用户打开页面而生成完整报告。

### 10. 分级事实和严重负面护栏

满足主体、来源、证据、Schema 和版本化自动路由策略的低风险或中风险例行事实，可以进入平台共享事实层。以下内容只显示为明确标识的待核实线索，不得自动成为已核实事实：

- 严重负面或可能实质影响持续经营、估值和退出的内容；
- 主体歧义、来源冲突、证据不足或数字异常；
- 单一低质量来源的指控；
- 链接失效、撤稿、纠错或后续结论不明的内容。

`AUTO_PUBLISH_ENABLED=false` 继续作为默认运行配置。这里的“自动路由例行事实”不等于恢复无条件自动发布；任何扩大发布边界的改变必须另行决策和测试。

### 11. 事实、模型解读和报告分离

1. 事实层保存可复核的结构化变化和证据。
2. 模型解读是有版本、可撤下的派生内容，不改写事实。
3. 完整报告只有用户明确请求时才生成；普通公司页面不因访问自动调用模型。
4. 缓存命中、内容无变化或没有达到重要性阈值时，模型调用为 0。

### 12. 共享缓存与私有作用域

同一工商主体仍使用一个全局 `company_id`。可合法复用的公开事实、公开证据元数据和研究缓存可以跨有权限的平台客户复用；个人上传、机构资料、投资关系、私有线索和许可受限内容继续按个人或机构作用域隔离。

搜索 Provider 和模型不得因某一基金首先提交公司，就把公共公司档案锁定给该基金；也不得因公共事实可共享，自动公开其私有原始文档或投资信息。

### 13. 用量、成本和审计

每个任务至少记录：

- 发起用户、目标公司、身份版本和任务原因；
- Provider、查询、请求时间、响应状态、缓存命中和重试；
- URL、来源、字节、哈希、许可状态和抓取结果；
- 模型、提示词/Schema 版本、参数、Token、延迟和估算费用；
- 每阶段开始、完成、取消、失败和停止原因；
- 产生的候选、事实、线索、证据和去重关系。

用户取消不退还已经发生的外部成本；只有尚未发生外部调用时，才可以按现有额度规则退还相应月度额度。已验证中间结果可安全复用，防止重复取消制造额外调用。

### 14. 天眼查安全退役边界

1. 新功能不得启用、扩展或依赖天眼查 API、CLI、MCP、Skill 或返回格式。
2. 当前专用开关保持关闭；正式退役由独立代码里程碑完成，不在本 ADR 文档 PR 中删除代码或数据。
3. 退役时删除活动运行时代码、配置、Secret、缓存、CLI、部署接线、CI 和用户可见供应商文案。
4. 不重写已经应用的 Alembic 历史迁移；必须使用新的向前迁移停用专用数据库行为。
5. 必要审计历史和原始血缘可以保留，但不得继续向普通用户展示仅由该供应商支撑且无法独立复核的事实。
6. 不得把历史天眼查证据静默改名为“公开网络来源”或“官方来源”。

## 开源项目借鉴边界

本项目只借鉴以下工程思想，不引入完整依赖：

| 项目 | 借鉴 | 不采用的原因 |
| --- | --- | --- |
| Pi | 模型适配、调用生命周期和可观测性 | 自主工具型运行方式缺少本项目所需的证据、权限和发布闸门 |
| Deep Agents / LangGraph | 持久化状态、检查点、中断和中间件 | V1 已有 PostgreSQL 状态机，引入图运行时会产生双状态源 |
| GPT Researcher | 计划、执行、来源追踪和报告分层 | 以长报告为中心，默认成本和范围大于当前按需事实更新 |
| Vane | 检索、引用和进度反馈 | 聊天式引用不足以替代结构化证据血缘和 RLS |
| SearXNG | 统一搜索接口，可作为开发或备用候选 | 依赖上游搜索源，稳定性、许可和中文覆盖仍需实测 |
| Crawl4AI | 复杂页面内容提取思路 | V1 先复用现有安全抓取器；浏览器执行面和安全维护成本更高 |

开源架构只作为设计参考。任何新依赖仍须通过安全、许可、成本、维护和真实样本闸门。

## 分阶段交付

1. **ADR 文档检查点**：接受本决策并同步项目计划；PR #42 保持 Draft 战略暂停。
2. **天眼查安全退役**：关闭并移除活动集成，保留历史迁移和必要审计，验证现有查询、证据、共享和权限不回归。
3. **搜索数据源准入与实样验证**：使用同一批真实中国公司比较候选 Provider 的覆盖、来源、稳定性、许可、成本和错误处理；未达门槛不编码适配器。
4. **受限公开网络研究 Agent V1**：在现有 PostgreSQL Worker 上实现固定计划、有限补缺、工具白名单、证据约束、预算和进度。
5. **恢复 M6B 独立用户复测**：用原外部用户提交完成身份、排队、进度、取消、断线恢复和内容价值复测。

每阶段使用独立 PR，可单独测试和回滚；上一个闸门未通过时，不提前展开下一阶段。

## 验收合同

后续代码实现至少证明：

1. 同步搜索和详情的外部调用、模型调用均为 0；
2. 未核验或身份歧义公司不能进入自动研究；
3. 同公司重复请求复用任务、缓存和事实，不重复花费；
4. 每个运行受到搜索、文档、字节、时间、Token 和费用上限约束；
5. 搜索摘要不能直接成为证据；每个已核实事实关联可展示证据；
6. 私网、危险重定向、受限来源和超大响应被阻断；
7. 模型输出 Schema、主体、数字、日期和证据校验失败时不发布；
8. 严重负面、冲突和证据不足内容只进入待核实线索；
9. 用户取消和断线恢复不产生重复外部调用；
10. 个人和机构私有内容不因同公司共享档案而泄露；
11. 用户未申请报告时不生成报告；
12. 所有调用、成本、候选、事实和停止原因可审计；
13. 当前基金路径、共享事实晋升/撤回和公司详情不回归；
14. 真实样本能证明每条有效重要变化的成本和人工复核量可接受。

## 非目标

- 通用全网爬虫或不受限的自主 Agent；
- 绕过 GSXT、验证码、登录、付费墙或反自动化机制；
- 每日扫描全部公司；
- 动态加载任意 MCP、Skill 或工具；
- 自动生成或发布严重负面结论；
- 因页面访问自动生成完整报告；
- 立即采用 Pi、LangGraph、Deep Agents 或 Crawl4AI 作为运行时；
- 在本阶段开发订阅、支付、organization 重构或消息通知。

## 后果与风险

正面结果：

- 降低单一供应商额度、价格和接口变化对产品的控制；
- 复用现有任务、抓取、证据、RLS 和模型校验能力，减少重构；
- 通过固定计划、缓存、有限补缺和按需模型降低调用成本；
- 用户能看到可恢复进度，系统仍保持异步和可取消；
- 搜索、事实、模型解读和报告解耦，便于替换 Provider 和模型。

主要风险：

- 公开网络资料覆盖和质量不如结构化商业数据库稳定；
- 搜索 Provider 的中文覆盖、许可和成本尚未实测；
- 同一事实的多来源去重和时间语义可能增加人工例外；
- 复杂网页可能超过现有抓取器能力。

这些风险由真实样本准入、白名单工具、明确预算、证据校验和保守发布规则控制，而不是通过扩大 Agent 自主权解决。

## 回滚

本 ADR 在代码实施前可通过新 ADR 取代。后续每个代码 PR 必须独立可回滚；数据库变更只新增向前迁移，不改历史迁移。应用回滚优先回退镜像并保留向前兼容数据库结构，不直接对真实数据执行未经评估的 downgrade。

## 待后续闸门回答的问题

以下问题不阻塞本 ADR，但必须在搜索数据源准入里程碑用真实样本回答：

1. 中文企业公开信息搜索的主 Provider 和人工备用来源；
2. 搜索结果缓存、展示和派生使用的许可边界；
3. 100、1,000 和 10,000 家公司的调用成本与限流；
4. 新闻、政府、官网、司法和监管来源的覆盖缺口；
5. 何时需要在现有安全抓取器之外引入浏览器型提取工具。

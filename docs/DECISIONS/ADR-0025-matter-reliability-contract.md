# ADR-0025：资料到公司事项的证据、比较及当前展示契约

- 状态：负责人 2026-09-22 明确要求按其《资料→公司事项可靠性改造提示词》实施本地 A→B→C；批次验收状态以有效看板为准。替代上一轮尚未实施的宽泛 E4.9 建议。
- 保留 FastAPI/PostgreSQL、权限/证据血缘、人工确认、预算账本及后台更新架构。当前仅本地工程授权；不调用真实供应商，不部署或改生产数据/开关。

## 决定

1. 证据片段按原始 UTF-8 字节 SHA-256，不修剪空白、不改变换行或 Unicode；对象指纹另按排序 JSON 编码计算。旧 matter-v1 仅在可识别的旧元数据、匹配旧算法及原摘录时兼容，未知版本/篡改/越界仍失败。旧数据仅提供本地只读扫描，不重写历史哈希。
2. 事实支持分开记录引用完整性、主体角色、字段语义、规范化转换及来源日期；规范标签通过受限类型/动作映射核验。supported 表示该字段有证据支持，不代表已发布、可靠来源或人工确认。
3. 当前读取以仍授权且有效的字段支持为准。撤回不删除历史；原始 Event/导入事实不被自动修改。新增字段、冲突、否认及更正提议分别记录；失效证据不能继续通过旧摘要、报告或解读泄露为当前事实。
4. 候选生成与独立校验分开；模型使用受限类型/角色及逐字定位，字段失败不拖垮其他有效字段，主体/动作错误拒绝该候选。模型默认关闭，仅 Mock 和已许可旧响应可离线使用，不使用已封存新留出样本调规则。
5. 将事项身份判断与字段差异判断分开：同轮次/相近报道日期不是充分身份依据。缺字段保持未知；金额冲突有充分交易锚点才记录为同事项冲突，否则保留关联不确定。观测区分原始片段、业务主张、处理版本，保留并发锁及数据库约束。
6. **产品语义调整（C 批，本地实现）**：取得可用原文且主体/具体事项有依据时，发生日或来源日未知不再直接丢弃；可保留为历史/时间未知候选。已知旧事新报保持旧发生时间。来源检查、首次收录、近期事件分别记录，历史/未知候选不刷新近期事件状态。此项补充 ADR-0024 的“无近期日期不新建”限制，不授予新的公开展示或自动发布权限。
7. 每份材料保留结构化处置原因，沿用原始文档/任务记录；不另建平行工作流系统。人工复核按现有策略处理争议，不将单纯日期缺失或确定性重复一概交给负责人。

## 顺序及验收

A：真实入库→账本→读取的失败回归，哈希/旧格式/共享引用/字段语义/部分撤证。
B：A 核心回归通过后，实现候选校验、预算窗口/缓存版本、事项比较和观测幂等，验证真实 PostgreSQL/RLS。
C：B 核心回归通过后，实现时间准入/处置/展示，完成虚构正文的追加、冲突、撤证演示及完整后端/前端回归。

工程正确性、封存正文质量和独立发现分开报告。原 3/9 与本轮已有 1/4 保留；Mock 不证明真实模型语义增益。迁移只允许新编号，先在一次性本地数据库验证；有新观测数据后不直接删除历史或降级到不识别新读取契约的版本。

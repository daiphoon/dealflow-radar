# ADR-0008：官方工商身份核验与歧义重路由

- 状态：已接受
- 日期：2026-07-16

## 背景

身份优先路由已会阻止不能唯一解析的记录，但缺少官方核验证据、候选选择和原记录重路由。[国家企业信用信息公示系统帮助](https://bt.gsxt.gov.cn/affiche-query-info-help-660000.html)说明社会公众可按企业名称或统一社会信用代码查询；[市场监管总局公示系统运行管理规则](https://www.samr.gov.cn/xyjgs/flfg/art/2023/art_f6972d9dbbf641168e71fab9de31cb7a.html)中的数据接口、批量导出和信息资源开放需按权限或审批执行。项目当前没有获得可用于后台自动查询的正式授权 API。

## 决定

1. 定义 `OfficialIdentityProvider`边界。V1 实现 Git 忽略私有目录中的官方查询结果 JSON 导入；得到正式 API 授权后只新增适配器，不改业务路由。
2. 不抓取验证码、登录页或未公开网站接口。导入只接受 HTTPS 的 `*.gsxt.gov.cn` 或 `*.gov.cn` 证据地址，并校验 18 位统一社会信用代码字符集和校验位。
3. 官方记录追加保存为 `raw_documents` 和 `official_identity_verifications`，保留查询词、工商全称、信用代码、注册地、登记状态、核验时间、匹配规则和原链接。表按租户执行 RLS，管理员可导入，审核员可读取候选。
4. 信用代码和工商全称/注册地一致时由程序自动核验；字段冲突保留为 `conflict`，不静默改主数据；无现有公司可匹配时保留为 `unmatched`，不自动创建公司。
5. 歧义工作台只展示 30 天内、与原始提及有确定关联且信用代码不冲突的官方候选。修改身份主数据和重路由要求同一用户同时具有 `reviewer` 和 `institution_admin` 角色，并强制保留理由、操作人和时间。
6. 选定候选后，同一事务内更新公司身份、保留曾用工商名、解析实体提及、从原 `raw_document` 重建事件/证据，并重用 ADR-0007 的发布策略。页面决定不访问外部网站；原来源 URL 未经检查时，重路由结果安全降级为 `unconfirmed_lead`，不进入已确认快照。
7. 官方身份鲜度默认 30 天，由 `IDENTITY_VERIFICATION_TTL_DAYS` 配置；策略版本由 `IDENTITY_POLICY_VERSION` 记录。

## 影响

身份审核从“人工重新研究整条事件”收敛为“在官方候选中选主体”，事件生成、去重、证据关联和发布路由均由程序完成。当前仍需将官方查询结果结构化导入；这是没有获得官方数据 API 授权时的合规边界，不应用抓取验证码或私有端点替代。

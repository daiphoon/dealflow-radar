# ADR-0011：公司主档全局复用，已核验法定名称进入共享身份索引

- 状态：已接受
- 日期：2026-07-19
- 关联：ADR-0008、ADR-0009、ADR-0010

## 背景

同一未上市公司可能被多个基金投资，也可能同时被个人和机构查询。基金可以引入一家公司，但不能因此拥有或锁定该公司的工商主体身份。现有全局公司主档已经允许多个基金通过独立 `investments` 行引用同一 `company_id`，但身份消歧确认公司更名时，旧工商全称被保存为来源机构私有别名，导致其他有平台访问资格的用户无法用已核验曾用名找到同一家公司。

公司身份复用与内容共享不是同一决定。共享工商身份不能自动共享引入机构的投资关系、候选事件、证据、原始文档或研究底稿。

## 决策

1. 工商主体是平台公司目录的主实体。同一工商主体原则上只有一个全局 `company_id`，统一社会信用代码是主要强标识；基金、组合、个人关注和机构业务数据只能引用公司，不拥有公司主档。
2. 已进入全局目录的公司继续使用 `tenant_id = NULL` 和兼容值 `visibility_scope = public`。这里的 `public` 表示平台共享目录，仍要求登录和有效访问资格，不表示互联网匿名公开。
3. 管理员通过既有身份工作台明确选择有效工商候选并完成身份确认时：
   - 当前工商全称写入全局公司主档；
   - 被替换的原工商全称以 `former_legal_name + verified + platform_shared` 保存；
   - 共享法定名称别名不设置 `owner_user_id` 或 `owner_tenant_id`；
   - 当前工商全称、已核验曾用名和统一社会信用代码均返回同一 `company_id`。
4. 只有全局目录公司的、经显式身份确认产生的法定曾用名进入共享身份索引。简称、品牌名、内部代号、来源文本中的模糊称呼及未核实名称继续保持个人或机构私有；V1 不自动提升这些别名。
5. 租户级私有公司的曾用名继续保存为 `organization_private`，由来源租户拥有。公司尚未获准进入全局目录时，不能因一次机构导入自动共享其名称。
6. 基金授权只控制基金私有叠加层。不同基金引用同一 `company_id` 时，可以复用共享工商身份；投资金额、持股比例、内部估值、机构备注、私有线索和私有资料仍按租户及基金授权隔离。
7. 公司身份、事件事实、证据引用和原始文档分别决定作用域。共享法定名称不会改变任何事件、证据或文档的作用域，也不会使来源机构成为共享公司主档的 owner。
8. 不批量提升历史私有别名。历史记录只有在可追溯的身份审核中确认其确属全局公司法定名称后，才按本规则写入共享索引；无法确认时维持原作用域。

## 实现与验证边界

- V1 复用现有 `companies`、`company_aliases`、共享别名唯一索引、搜索 API 和 RLS，不新增数据库表或迁移。
- 搜索仍为工商全称、统一社会信用代码和已核实共享别名的确定性精确搜索；无结果不创建公司、不调用外部 Provider。
- 必须自动验证：旧全称、新全称和信用代码命中同一 ID；无基金用户与另一机构均可命中；租户私有曾用名和内部别名不可跨 owner 搜索；两个基金只看到各自投资叠加层。
- 本决策不实现模糊搜索、品牌关系自动共享、公司自动收录、watchlist、订阅计费或事件自动发布。

## 兼容与回滚

- 当前基金、投资关系、共享事件、候选事件和原始文档不做迁移或回填，现有本地影子验证基金继续可用。
- 应用回滚不会删除已核验的共享法定名称。若某次身份决定本身错误，应通过可审计的身份纠错流程修正，不通过数据库降级或静默删除处理。
- 本里程碑没有 Alembic 迁移；现有数据库版本保持 `0013`。

## 后果与限制

- 收益：公司真正成为跨个人、机构和基金复用的数据库主实体；公司更名后仍可用历史法定名称准确找到同一主档；不会复制公司或泄露基金私有信息。
- 代价：共享名称严格依赖人工身份确认，尚未提供法定名称历史时间轴和通用纠错界面。
- 暂不解决：未经核验品牌名如何晋升、集团/子公司关系搜索、同一信用代码异常冲突和正式生产权益系统。

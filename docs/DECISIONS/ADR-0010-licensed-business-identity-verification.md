# ADR-0010：授权商业工商数据可作为独立身份核验依据

- 状态：已被 ADR-0018 取代，仅保留历史记录
- 日期：2026-07-19
- 关联：ADR-0007、ADR-0008、ADR-0009

> 2026-09-02：因供应商额度和商业可持续性不再满足产品路线，本决策的活动集成方向由 ADR-0018 取代。既有审计和已应用迁移不回写；现存实现由独立安全退役里程碑处理。

## 背景

现有 `OfficialIdentityProvider` 只接受政府或 GSXT 域名的人工 JSON。真实运营验证表明，系统已有导入、候选和重路由能力，但 10 家真实公司没有可稳定取得的政府结构化证据。项目负责人已确认取得天眼查 API 在本项目中的调用、本地持久化、缓存、订阅与机构展示、派生报告及合同终止后数据处理授权。

天眼查是商业聚合数据服务，不是登记机关。若仍统一显示为“官方核验”，会混淆证据等级；若完全不能用于核验，又会使已有授权数据无法解决现实身份缺口。

## 决策

1. 公司身份保留统一状态 `identity_status`，另增加可审计依据：
   - `official_government`：政府或登记机关直接来源；
   - `licensed_business_data`：具有明确授权的商业工商数据。
2. 页面分别显示“已核验（政府官方来源）”和“已核验（授权工商数据）”，不得把后者表述为政府官方核验。
3. 历史官方核验记录迁移时保守回填为 `official_government`；历史公司主档不猜测依据，保持空值，直至新证据确认。
4. 天眼查 V1 只通过本机受控后台命令运行，不进入公司搜索、公司详情或其他同步请求链路，不加入自动刷新任务。
5. 每家公司先按工商全称查询候选，再以统一社会信用代码精确锚定并查询登记信息。没有且仅有一个精确信用代码候选、返回代码不一致或必要字段缺失时，整条记录失败关闭。
6. 自动精确匹配只补齐缺失代码或地区，不静默改名。相同代码且工商全称相同时，地区格式或历史值差异单独记入匹配规则但不覆盖现有地区；相同代码但工商全称变化时记录 `conflict`，通过现有身份工作台人工选择并保留理由与曾用名。
7. 政府来源按 A 级、`public` 记录；天眼查授权数据按 B 级、`permission_confirmed` 记录。来源、查询时间、数据更新时间、登记机关、供应商公司 ID 和响应哈希可审计。
8. 供应商完整原始响应只保存于 Git 忽略、权限为 `700/600` 的本机私有缓存。业务数据库只保存核验所需字段、响应哈希和最小元数据，不保存返回的电话、邮箱、法定代表人等本里程碑不需要的字段。
9. 缓存默认 30 天。缓存键由工具和规范参数决定；命中缓存时外部调用为 0，缓存命中状态只写用量审计，不进入工商事实哈希。
10. 真实调用必须同时满足 `APP_MODE=demo`、`EXTERNAL_CALLS_ENABLED=true` 和 `TIANYANCHA_IDENTITY_CALLS_ENABLED=true`；付费、自动刷新、自动发布和可信来源监测开关必须关闭。`dry-run` 不读密钥、不连接数据库、不访问网络。
11. API Key 只通过本机环境变量或部署 Secret 注入，不进入 Git、数据库、响应或日志。HTTP 适配器只允许固定官方 Core 端点、两个批准工具、有限超时/重试/请求数和响应大小，不跟随重定向。
12. 身份核验本身不产生事件、共享事实或自动发布。严重负面事件仍须遵守 ADR-0007 及后续共享晋升的更严格证据规则；授权商业工商身份不能单独降低其发布门槛。

## 兼容与回滚

- 现有政府 JSON 未填写 `verification_basis` 时默认按 `official_government` 解析，导入契约保持兼容。
- `0013` 只新增依据字段和约束，不修改历史迁移、不批量改写公司主档、不改变 RLS 策略。
- 回滚应用时优先保留向前兼容数据库；执行数据库降级前必须备份。降级只移除新增依据字段，不删除原核验、原文档或公司。
- 当前影子基金、投资关系、共享事实和个人/机构双通道不受影响。

## 后果与限制

- 收益：10 家实样可以用同一受控入口核验；来源等级、许可和数据血缘不再混淆；重复运行可复用缓存并保持幂等。
- 代价：V1 仍需管理员准备私有查询清单并手工运行；供应商失败且数据库事务未开始或已回滚时，调用痕迹只存在私有缓存/命令错误，不构成完整生产级请求审计。
- 暂不实现：通用商业数据 Provider 平台、自动调度、联系人字段、工商变更订阅、正式认证、计费和供应商自动切换。

# ADR-0020：系统负责公开资料主体查证

- 状态：产品方向已确认；实现及生产启用分别验收。
- 补充 ADR-0018/0019；不恢复旧商业数据源，不要求用户提交营业执照扫描件。

## 决定与边界

用户提供工商全称和统一社会信用代码，后台负责查证；同步申请只保存请求。现有受限研究 Worker 在无可执行公司研究任务时，处理尚未绑定公司的申请。代码格式正确不等于身份真实；搜索摘要、用户输入和模型猜测均不能作为核验依据。

最小交叉核对条件：安全读取的页面正文中，公司全称附近出现有标签的对应信用代码；另一个独立域名的政府页面正文出现相同工商全称；已读资料没有代码冲突。核对结果新增 `public_crosscheck` 依据，界面明确显示“主体已交叉核对（公开资料，非官方登记核验）”。不推断登记状态、注册地或当前股东，不写入 `official_identity_verifications`，不冒充政府实时登记核验。

只有上述条件通过，才创建唯一信用代码的共享基础公司并接入现有研究队列。现存私有档案、同名异码及冲突不自动合并、覆盖或批量晋升，返回统一的进一步核对提示，不泄露私有档案是否存在。历史官方/交易所核验路径保留。

资料不足也允许后台先查找并保存候选 URL 和最小身份摘录，但不生成公司事件或共享快照。预算耗尽仍无法判断时，明确告知“平台保留进度待补证”，不要求上传执照、不伪称成功，也不无限重试。真实冲突才要求核对输入。公开来源是否足以覆盖具体公司，必须实测；本规则不能保证每家公司自动通过。

## 成本、取消与恢复

- 复用百度主源、失败时博查回退；身份阶段最多两次搜索，沿用网页字节/请求上限、HTTPS、DNS/SSRF、robots、MIME 和超时检查。身份搜索不限制为最近一年，业务变化搜索仍保留近期窗口。
- 身份阶段消耗从后续同一次研究预算扣除，不新增总额度，不调用模型，不自动发布或生成报告。开关、Worker 角色及日/月预算保持原边界。
- 先持久化调用预留再联网；正常结果记录用量，进程意外中断时保留不确定调用并停止自动重试，交运营确认。取消发生在网络步骤中时，保存已取得资料后停止，不再创建公司或发出新调用；关闭页面与退出登录不取消任务。
- 完全相同名称/代码的在途申请等待先前查证；现有有效公开查证材料可复用，期限沿用文档缓存配置。不得复用任何用户上传私有材料或把他人请求信息返回客户端；robots 缓存不跨请求复用。

## 数据与权限

新增 `identity_research_states`，以申请 ID 为主键，保存策略、输入哈希、阶段、候选、来源正文最小摘录/哈希/检查时间、预算和核对决定。只有有效平台管理员通过 RLS 读写；身份查证用量明细也限制为平台管理员读取，避免从账本暴露他人申请 ID。用户只读取自己的原申请及经过筛选的状态说明，不返回底稿 JSON。公司公开层只增加明确的核对依据标签。

`0027` 只新增该表、管理员专用策略和公司依据约束；不修改历史迁移，不改现存公司/基金/投资关系。新资料存在时禁止直接降级删除血缘；优先应用回退并保留数据库结构，真实部署前必须备份。没有新资料时验证升级、Schema 检查和降级。

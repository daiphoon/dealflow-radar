# ADR-0021：增量交付与事件处理链局部重构

- 状态：已接受，实施按切片验收；本次只完成规划文档。

- 依据：项目负责人确认采用仓库审查后的“增量交付＋局部重构”建议。
- 补充：ADR-0017、ADR-0018、ADR-0020；保留身份、权限、供应商退役、预算及发布边界。
- 推进顺序：取代旧看板中继续逐个修补搜索/抓取后直接进入 M6B 的待办顺序；不改写既有交付和验收历史。

## 背景

本地 `main@0a2344b` 的只读审查确认：项目已有稳定公司身份、PostgreSQL 任务与作用域隔离、事件和证据模型、独立模型解读、个人页面及模板报告，适合继续演进。当前主要缺口在数据处理链：差分检测器没有接入活动业务入口；公开网络事件按 URL/内容哈希识别，事实字段主要为页面标题；重要变化展示与旧生成路由绑定；类别持续监控和搜索费用计量尚未形成完整闭环。

研究 PDF 与增量任务书是方向及验收参考，不是仓库现状证明，也不是命令执行授权。报告中的报价、规模、频率、评分和商业预期不直接成为运行配置。

## 决策

1. 保留现有项目、技术栈、内部公司 ID、CloudBase 身份认证、本地授权/RLS、证据血缘、队列、缓存、取消恢复、页面和部署体系。除当前切片必需部分外，不重命名、重排或重写模块。
2. 在现有单体内，分批补齐“资料标准化/事实抽取 → 业务事件归并及修订 → 证据与发布校验 → 现有页面、解读、报告”。结构化快照先做确定性差分；公告等非结构化资料先抽取候选事实。两条路径共享事件契约，不要求网页先变成工商快照。
3. 先做一类事件闭环，再补类别来源覆盖、真实成本口径及预算预占，然后接关注公司的低频检查并恢复真实用户价值验证。机构私有导入和组合报告仅在客户资料与需求成立后启动。
4. 保留九类事件枚举；股权/股东、IPO、融资、司法、高管、合同/中标六类只是逐批接入优先范围，不要求首批全部覆盖，也不删除其他已有类别。
5. 业务事件身份与网页身份分开：同一事项可关联多个来源；转载不算独立确认；不同案号、项目、标段或程序节点不得误合并。实质更正追加版本和依据，历史数据不静默覆盖。
6. 补充 ADR-0017 的目标展示语义：达到现有主体、证据、权限和发布条件的重要业务事件，应能进入重要变化层，不永久限定为旧 `deterministic_change` 生成机制。具体字段/API 兼容方案在 E1 切片确定。此决策不把候选改为已确认、不改变评分阈值、不开启自动发布；不符合既有发布规则的内容继续保留为未确认线索。扩大可自动发布范围必须另行决策。
7. 搜索发现、成功读到正文、证据支持、事件发布、用户价值分别验收。费用未知不能计作已证实的零成本；扩大并发或开启定时调用前，先验证额度预占、结算与中断处理。
8. 使用兼容式迁移、显式的新路径开关和原有读取路径渐进切换。保留已应用迁移、历史指纹、事件 ID、报告与审计。回退先关闭新路径或回退应用，不能删除新证据或重新启用旧昂贵路径。

## 不采用的方案

| 方案 | 主要代价 | 决定 |
| --- | --- | --- |
| 推倒重写或换栈 | 身份、权限、迁移、证据和恢复重新验收，仍不能解决来源缺失 | 不采用；只有不可兼容的约束经测量证明后再作新 ADR |
| 持续逐公司追加关键词和抓取特例 | 无法替代业务事件结构、跨来源归并和覆盖验证 | 仅允许当前切片被可复现问题阻塞时的必要修复 |
| 原样执行任务书全部批次 | 重复建设已有功能，提前扩大数据源和产品范围 | 映射真实缺口后按切片执行 |
| 新队列、通用 Agent、向量库或全量每日扫描 | 增加运行状态、费用与维护面，缺少容量依据 | 保留既有非目标 |

## A：证据和当前事实

- 引文采用精确 UTF-8 字节 SHA-256；排序 JSON 仅作对象指纹。版本、中文引号、换行与空白独立检验。
- 旧 `matter-v1` 仅在旧对象哈希、完整旧观测指纹、原文定位一致时兼容。未知版本、篡改、越界、断裂/循环共享引用不放行。不重算写回旧证据。
- 规范字段名不必逐字出现在原文；按类型校验动作、金额角色、轮次、主体和状态。金额比较保留币种和“近/约/不超过”等口径，转换过程记录版本、原值和定位。
- 字段支持与发布资格分开。部分撤证后按仍有效的引用重建当前字段和摘要；撤回金额的全部支持后，当前字段与账本不再沿用该金额。原始 Event/人工记录不覆盖。
- 相互矛盾的有效金额均标为冲突，不自动选后到的一方。引用撤回后重新计算剩余支持。新事项暂不调用旧模型解读路径，现有读取不显示旧的事项解读缓存；可选的事项模型解读需要后续接入当前有效字段后再启用，本轮不宣称完成该功能。

## B：候选、身份比较与观测版本

- 新模型提议要求有类型的动作、主体角色及状态，由独立验证器检验。合法的“筹得融资资金”等规则未识别表述可以产生有支持字段。旧封存输出有显式兼容入口；新请求不能退回旧规则来决定提议是否成立。
- 错误字段单独剔除并记录原因；主体、动作、来源定位错误拒绝候选。接收融资/投资方、买方/被收购方、品牌/法人、IPO 申请及其他阶段分别处理。同段多事项及局部否认有回归。
- 模型输入按主体选择带上下文的有界窗口，保留偏移和截断原因；预算不足明确记录规则降级。缓存身份包含正文、主体、提示、结构、模型、Provider 与实际请求配置；仅改变校验版本时可零调用复核已结算输出。未知支出不自动重试，相同内容的缓存检查与预占用数据库锁串行化。
- `MergeDecision` 区分新事项、补来源、补字段、进展、更正提议、冲突和身份不明。同轮次或相近报道日期不够；有明确交易/项目锚点后才解释金额冲突或阶段进展。删除原来的 45 天报道日期归并限制。
- 新迁移 `0035` 分离 `observation_key`、`processing_version` 与 `schema_version`。同一原文可追加新字段/处理版本，重复执行幂等；同引文复用证据行，观测及证据投影历史追加保存。同 URL 正文变化保留新的 RawDocument。已撤证或撤回事项不因重跑恢复。
- 新迁移不改变现有 RLS 策略。用非 owner、非 superuser、非 BYPASSRLS 角色验证普通用户不可读取受限原文/内部观测，也不可伪造观测；并发测试使用真实 PostgreSQL。

## C：资料保留、时间与展示

有具体主体、动作及原文支持的历史或未知日期材料可作为未确认事项保留。实际发生日、来源发布日期、发现时间分别保存；未知不补造成抓取日。旧事新报仍为历史，计划/未来时间不作为已发生事件，单纯时间未知不新建人工复核任务。这是 ADR-0025 明确覆盖 ADR-0024 原“无近期日期不新建”规则的产品语义调整。

处置沿用已有任务覆盖元数据、用量账本和观测，不改不可变原始正文。记录获取、候选、输入截断、字段拒绝、比较、保留/抑制与展示原因。模型原始输出及拒绝原因存于受限账本；不向普通用户暴露任务内部文本。没有任务对象的离线入口，由测试演示收集处置，持久观测保留关联决策。

现有公司详情区分“人工整理、负责人已复核”“原文支持的未确认事项”和未确认线索；时间口径与来源载体分别显示。官方域名不覆盖 AI 生成、用户投稿或转载属性。不能明确识别发布类型时保留未知，不凭域名直接升级可信度。未确认事项不进入已确认报告或公司快照。

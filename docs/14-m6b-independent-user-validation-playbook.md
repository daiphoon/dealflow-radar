# M6B 独立邀请用户验证手册

## 1. 本阶段要回答的问题

M6B 不再证明“网站能不能运行”，而是验证三个真实产品问题：

1. 一个没有接受过项目培训的目标用户，能否自己完成登录、找公司、读懂重要变化和核对证据；
2. 页面提供的“重要变化 + 证据 + AI 解读”是否比用户自己翻查工商网站、新闻和商业信息网站更省时间、更容易理解；
3. 用户是否愿意在以后遇到真实查询需求时再次使用，而不是只在测试当天配合完成任务。

本轮属于邀请制运营验证，不开发订阅、支付、机构自助管理或新数据 Provider。发现问题时只修复 P0/P1；P2 汇总后再决定，不在测试现场扩张功能。

## 2. 测试分段与样本

### 2.1 第一段：3 名独立个人

三名测试者必须使用自己的账户、设备和判断，不得是项目负责人控制的第二邮箱或第二手机号。优先构成：

- 2 名 40—60 岁、持有或关注未上市公司股权的个人投资者；
- 1 名有股权投资、基金、财务、法律或企业管理经验的人。

如果暂时找不到完全符合的人，可以邀请一名具备真实投资信息需求的熟人替代，但不得把项目开发者或已接受详细产品培训的人计为独立测试者。

### 2.2 第二段：扩大到 5—10 名

只有第一段满足以下条件才扩大：

- P0 为 0；
- 登录、搜索、公司详情或证据查看没有尚未解决的 P1；
- 三人都能在不由项目负责人代替操作的情况下完成核心路径；
- 至少两人能准确复述一条重要变化、证据来源及不确定性；
- 至少两人能说出一个相对现有查询方式的具体增值点。

未达到时先根据证据决定是修复流程、补内容标准，还是调整产品方向，不用增加人数掩盖问题。

### 2.3 当前恢复闸门

截至 2026-09-04，R3 已证明新公司申请能够进入持久化研究队列，并支持进度、取消、断线恢复、预算控制和搜索源回退。R3.1 已将北京智齿博创的旧噪声隔离，并在卧安机器人生产复测中证明百度主源可用、商业资料页不再进入抓取队列。R3.2 已通过 NFKC 主体匹配和精确上市阶段词修复递表、通过聆讯、备案和招股等高价值结果的误拒绝；剩余阻塞是部分目标页面按 robots 禁止普通自动客户端读取正文，以及正式披露位于尚未解析的官方 PDF。

因此，M6B 当前结论仍为 `修复后复测`。R3.1、R3.2 已关闭；恢复 U01—U03 前依次完成 R3.3—R3.5，当前只实施 R3.3：

1. 不绕过 robots；搜索摘要、受阻页面和通用首页不得生成事实；
2. 优先从现有主备缓存定位政府、监管、交易所、公司官网、正式 Feed 或官方 PDF，不默认增加搜索调用；
3. 使用卧安机器人现有搜索缓存回放，百度和博查新增搜索调用必须均为 0；
4. 主体、来源日期、明确变化和原始证据必须同时成立；无法取得时明确显示可审计的证据缺口。

R3.3 通过前，不查询第二家新公司，不增加 Provider 或模型，不新增独立测试者，也不以“任务已完成”替代内容价值验收。

## 3. 测试前准备

### 3.1 账户与隐私

- 每人先以独立邮箱建立受邀 CloudBase 账户；如测试者愿意，再把手机号安全绑定到同一账户后测试手机验证码。手机号不能绕过邀请或自动注册第二个账户，邮箱继续作为恢复路径；
- 真实邮箱、手机号、姓名和反馈录音不得提交 Git；只在 Git 忽略的 `data/private/m6b-validation/` 保存；
- 仓库文档只使用 `U01`、`U02`、`U03` 等代号；
- 不收集真实投资金额、持股比例、身份证件或投资协议；
- 测试前说明：这是香港邀请测试环境，内容用于信息参考和产品验证，不构成投资建议。

### 3.2 公司任务

每名测试者准备：

1. 一家自己确实关心的未上市公司；
2. 能找到时提供工商全称和统一社会信用代码；
3. 另从现有共享目录选择一家有内容的公司完成首次无引导体验。

若真实目标公司尚未收录，只提交准确主体并保存申请，不在同步页面等待外部查询。必须先由平台管理员把申请关联到已核验且允许共享的准确工商主体；R3.1 通过后，外部搜索仍只在独立 Worker 的预算、缓存和安全开关全部满足时运行，V1 不调用模型。不得为了现场演示绕过身份核验、直接写库、让搜索摘要替代原网页证据，或把未通过正文和变化质量闸门的候选展示给用户。

### 3.3 运行边界

- `PAID_API_CALLS_ENABLED=false`；
- `EXTERNAL_CALLS_ENABLED=false`；
- `AUTO_REFRESH_ENABLED=false`；
- `AUTO_PUBLISH_ENABLED=false`；
- 同步搜索和详情只读数据库；
- 真实外部研究只允许管理员在一次性受控窗口中开启相应独立开关，完成后立即关闭并核对用量；
- 测试前确认健康检查、备份、告警和回退路径正常。

## 4. 单人测试流程

首次体验应“少提示、先观察”。主持人只告知网站地址和测试目标，不先演示按钮位置；只有测试者明确卡住时才提供帮助并记录一次介入。

| 阶段 | 测试者任务 | 通过标准 |
| --- | --- | --- |
| 登录 | 自己选择手机号或邮箱验证码登录 | 能理解流程并进入首页；失败提示能指导恢复 |
| 找公司 | 用日常简称或名称片段寻找指定公司 | 能从建议中辨认工商全称和地区，不选错主体 |
| 核对身份 | 打开公司页，核对工商全称、信用代码、地区和数据时间 | 能说明自己正在看哪一个工商主体 |
| 读重要变化 | 阅读页面首屏的重要变化，以及存在时的 AI 解读 | 能用自己的话说明“发生了什么、为什么重要、哪里尚不确定” |
| 看证据 | 打开一条平台证据详情，必要时再打开外部来源 | 能区分平台整理、原始证据和 AI 解读，不把链接可点击等同于事实已核验 |
| 关注与回访 | 关注公司、刷新或重新登录后查看，再取消关注 | 本人状态可恢复；关注和取消均成功；不影响其他账户 |
| 报告 | 只有测试者确实想进一步阅读时才生成报告 | 中文排版可读，无 Markdown 残留、内部枚举或私有投资字段 |
| 真实需求 | 搜索其真正关心的公司；未收录时提交准确主体 | 无结果不自动创建错误公司；请求状态和后续流程清楚 |

机构投资叠加不纳入三名个人的首轮价值评分，由既有机构账户做一次回归即可。

## 5. 必须记录的指标

每名测试者使用[单次测试记录模板](templates/m6b-test-session.md)，记录实际发生的结果，不事后猜测：

- 登录、找到公司、读懂首条重要变化、打开证据所需时间；
- 每个任务是否首次独立完成、需要帮助的次数和卡住位置；
- 搜错主体、无结果、错误建议和页面错误数量；
- 测试者能否准确复述重要变化、证据和不确定性；
- 内容价值、易懂程度、可信程度（各 1—5 分）及评分理由；
- 相比其现有方法具体节省了什么，仍缺少什么；
- 是否愿意在真实需求出现时再次使用，以及愿意再次使用的条件；
- 外部搜索/抓取调用、模型 Token、费用、自动发布次数；
- 测试后发现的 P0/P1/P2。

“愿意付多少钱”只作为探索问题，不把口头意愿当作定价或付费验证。

## 6. 缺陷等级与停止规则

### P0：立即停止相关测试

- A 公司的资料挂到 B 公司；
- 个人看见基金投资金额、基金持股、内部估值、机构备注、其他用户资料或私有候选；
- 证据不支持的内容被展示为已确认事实；
- 被撤回或拒绝的事实仍向个人展示；
- 未授权账户取得访问，或发生未经允许的外部调用、模型调用、付费调用或自动发布。

### P1：修复并复测后再扩大

- 受邀用户无法完成登录；
- 合理简称无法找到已收录公司，或建议足以导致选错公司；
- 公司详情、重要变化或证据打不开；
- 重要内容因术语、排版或状态文案而被测试者实质误解；
- 关注、取消、回访或账户状态不能恢复；
- 未收录公司申请成功后没有真实进入身份/研究队列，或页面无法说明当前阶段、下一动作和是否仍在处理。
- 用户可见待核实内容主要由导航、静态企业资料、其他主体内容或没有明确时间变化语义的文字构成。

### P2：记录并集中决策

- 不阻断理解的文案、间距、排序和样式问题；
- 测试者提出但尚无重复证据的普通功能建议；
- 当前公司资料不足，但页面没有错误或误导。

## 7. M6B 结论闸门

### 7.1 第一段结论

三名测试者完成后，必须只给出以下一种结论：

- `扩大到 5—10 名`：满足 2.2 的全部条件；
- `修复后复测`：没有 P0，但存在 P1；
- `先调整内容标准`：流程可用，但多数人认为内容没有实际增值；
- `停止邀请并处理安全问题`：出现任一 P0。

### 7.2 M6B 完成条件

扩大样本后，只有同时满足以下条件才可以建议项目负责人评估 M7：

- 至少 5 名独立目标用户完成测试；
- P0 为 0，所有影响核心路径的 P1 已复测关闭；
- 至少 80% 的测试者无需代操作即可完成登录、找公司、读重要变化和看证据；
- 至少 60% 的测试者能指出一个具体、可复述的产品增值点，并表示有真实需求时愿意再次使用；
- 主体错误、私有数据泄露和无证据事实均为 0；
- 外部调用、Token、费用和人工运营时间均可追溯，未突破既定预算；
- 当前许可边界足以支持邀请测试中的实际展示方式。

达到这些条件只代表可以讨论 M7，不等于已经适合公开收费上线。定价、订阅权益、支付、服务条款和公开上线仍须另行决策。

## 8. 主持人话术边界

开场只说明：

> 请把它当成第一次接触的网站，按你平时查一家未上市公司的方式操作。遇到不明白的地方可以说出来，我先记录，除非你无法继续，否则不马上指导。

结束时只追问事实：

1. 你刚才看到的最重要变化是什么？
2. 你根据什么证据相信或不相信它？
3. 相比你平时的查询方法，哪里更省事，哪里更麻烦？
4. 哪些内容你看不懂或不敢据此判断？
5. 下次有真实公司要查时，你会不会再用？为什么？

不得引导测试者夸奖产品，也不得在其回答前解释产品“应该有的价值”。

## 9. 可直接发送的邀请文字

> 我正在测试一个面向未上市公司股东和投资者的信息查询网站，想邀请你独立试用一次。测试不是让你评价页面好不好看，而是看你能否自己找到公司、读懂近期重要变化并核对来源。整个过程大约完成一家公司即可，不需要提供投资金额、持股比例或身份证件。网站目前是香港邀请测试环境，内容只供信息参考，不构成投资建议；测试中会记录操作是否顺利和你的反馈，但不会把手机号、邮箱或姓名提交到代码仓库。若你愿意，请告诉我一个用于接收邀请和账户恢复的邮箱，以及一家你确实想了解的未上市公司工商全称或统一社会信用代码。手机号登录可以在账户建立后自愿绑定，不需要在邀请消息里发送手机号。

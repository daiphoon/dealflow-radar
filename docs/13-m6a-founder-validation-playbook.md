# M6A 创始人自测与真实内容价值基线

## 1. 目标与边界

M6A 是 M6 邀请制真实用户测试的第一段运营验证。它回答三个问题：

1. 一个没有基金权限的个人，能否独立完成登录、查公司、读事实、看证据、关注、回访和生成报告；
2. 当前真实共享目录中的内容，是否已经足以帮助投资者减少查找和核对资料的时间；
3. 在邀请其他人之前，是否存在主体错误、私有数据泄露、证据不足或核心流程阻断。

M6A 不是独立用户需求验证。项目负责人控制的多个邮箱只能算多个技术账户，不能算多名独立测试用户。M6A 完成后仍须通过 M6B 的独立邀请用户验证，才可以评估是否进入 M7。

本轮不开发订阅、支付、机构自助管理、自动全网检索或自动发布。认证方式的调整单独决策，不得与内容价值结论混为一谈。

## 2. 样本与账户

### 2.1 账户

- 账户 A：现有无基金个人账户，用于完整主路径；
- 账户 B：由项目负责人控制的第二个受邀邮箱，用于验证账户隔离和首次登录；
- 机构账户和平台管理员：只做既有权限回归，不参与个人价值评分；
- 测试记录不得保存邮箱验证码、Cookie、访问令牌、密码或完整手机号。

### 2.2 公司样本

从生产环境已核验且明确进入平台共享目录的真实公司中固定选择 10—12 家，不临时更换以迎合结果。样本尽量覆盖：

- 至少 3 个行业和 3 个地区；
- 常用简称与工商全称差异明显的公司；
- 有内容与内容稀少的公司；
- 有官网、政府或其他允许展示来源的公司；
- 至少 2 家项目负责人熟悉、可核对已知事实的公司；
- 身份歧义或未进入共享目录的公司只用于负向测试，不计入正常内容样本。

不得伪造事件、修改真实工商身份，或为了让页面显得丰富而降低共享事实晋升标准。

## 3. 测试前置条件

- 香港邀请测试环境健康，HTTPS、数据库和备份机制正常；
- `EXTERNAL_CALLS_ENABLED=false`；
- `PAID_API_CALLS_ENABLED=false`；
- `AUTO_REFRESH_ENABLED=false`；
- `AUTO_PUBLISH_ENABLED=false`；
- 只读取已持久化的平台共享公司和共享事实；
- 个人页面不得返回基金投资、持股、内部估值、机构备注、私有文档或私有候选；
- 测试时发现 P0 问题应立即停止相关路径，不继续扩大样本。

## 4. 一次完整自测流程

每个动作使用[测试记录模板](templates/m6a-test-session.md)记录开始时间、结束时间、结果和需要帮助的次数。

| 步骤 | 操作 | 预期结果 |
| --- | --- | --- |
| 1 | 使用受邀个人账户登录 | 验证码一次有效；失败时文案明确；登录后回到原目标页面；第二次访问在有效会话内不要求重复登录 |
| 2 | 使用工商全称搜索 | 返回唯一正确公司，不创建新公司，不调用外部数据源 |
| 3 | 使用常用简称或名称片段搜索 | 展示一个或多个可选择的准确候选；用户可以看清工商全称和地区；拼写错误暂不作为 V1 必须能力 |
| 4 | 使用统一社会信用代码搜索 | 返回同一个 `company_id`；未进入共享目录的公司不出现 |
| 5 | 打开公司详情 | 工商主体、地区、信用代码、官网状态、数据时间清楚；没有基金也能读取共享基础层 |
| 6 | 阅读共享事件和证据 | 能回答“发生了什么、何时发生、来源是什么、有什么不确定性”；链接状态和许可警告准确 |
| 7 | 关注再取消关注 | 只改变本人关注状态，不授予新权限，不影响另一账户 |
| 8 | 查看变化并回访 | 首次建立个人水位；再次访问不重复把旧事件当作新变化；另一账户水位独立 |
| 9 | 生成固定报告 | 页面以正常中文排版呈现，不暴露 Markdown 符号；没有投资私有字段或不必要的英文分类 |
| 10 | 搜索不存在或未共享公司 | 显示清楚的无结果或申请收录入口；不自动创建、不自动绑定、不发起同步外部查询 |
| 11 | 退出后重新登录 | 旧会话失效，重新验证后仍映射到原个人账户，不产生重复用户 |

机构账户另做一次回归：同一共享公司保持同一个 `company_id`，有授权时可叠加本基金投资关系；无授权的基金和其他机构私有内容不可见。

## 5. 公司内容评分

每家公司只按页面实际内容评分，不把研究人员已知但页面没有呈现的事实算作系统价值。

| 维度 | 判定方法 |
| --- | --- |
| 主体准确 | 工商全称、信用代码和地区指向唯一正确主体 |
| 搜索可达 | 工商全称、信用代码以及合理简称中至少两种方式可以找到 |
| 有用事件 | 至少一条事实会影响对经营、融资、产品、治理、合规、资产或退出的理解，而不是只有无意义的更新时间 |
| 证据支持 | 页面谨慎表述能被允许展示的来源信息和最小摘录支持 |
| 容易理解 | 不查看后台、不询问开发者，也能用一句话复述事件意义 |
| 信息边界清楚 | “暂无可靠公开数据”“未自动验证”“链接失效”等状态没有被误解为正面结论或事实确认 |

内容判断使用三级结果：`有价值`、`价值有限`、`无可用内容`。每家公司必须写一句原因，避免只打分不留依据。

## 6. 指标与预设闸门

### 6.1 M6A 必须测量

- 首次登录完成时间、验证码送达时间、重发次数和人工帮助次数；
- 第二次访问是否仍保持有效登录；
- 工商全称、信用代码、合理简称的搜索成功数；
- 搜错主体数和搜索建议误导数；
- 有至少一条有用共享事件的公司数；
- 共享事件总数、有价值事件数和证据可点击数；
- 证据无法支持页面表述数、失效链接数和重复事件数；
- 报告生成成功数和报告中难懂英文/Markdown 残留数；
- 每家公司完成搜索、阅读、核证和报告所需时间；
- 外部查询、付费调用、模型 Token 和自动发布次数；
- 需要开发者解释或介入的步骤。

### 6.2 M6A 结论规则

M6A 不以“所有指标都漂亮”为完成条件，而以得到真实、可复核的基线和明确下一瓶颈为完成条件。结论分为：

- `可进入 M6B`：P0 为 0；两账户核心路径均通过；主体错误和私有泄露为 0；至少一半样本有一条项目负责人确认有价值且证据支持的共享事件；
- `修复后复测`：无 P0，但登录、搜索、详情、证据或报告存在阻断性 P1；
- `先补内容生产`：技术路径可用，但不足一半样本有可用共享事件，或证据支持明显不足；
- `停止邀请并处理安全问题`：出现错误主体、跨账户/跨机构私有数据泄露、无证据事实、撤回事实仍展示或未授权自动发布。

“至少一半”是 M6A 的最低邀请门槛，不代表商业上线标准；M6B 仍需要独立用户证明内容确实有用。

## 7. 缺陷分级和停止规则

### P0：立即停止

- A 公司的信息挂到 B 公司；
- 个人看到投资金额、持股、内部估值、机构备注、私有文档或私有候选；
- 证据不支持的事实被当作已确认事实展示；
- 被撤回事件仍出现在个人页面或报告；
- 未授权账户取得访问，或系统发生自动发布/意外外部付费调用。

### P1：修复后继续

- 受邀账户无法登录或验证码错误无法恢复；
- 合理简称无法通过搜索建议找到已共享公司；
- 正确公司详情、证据或报告打不开；
- 报告仍显示 Markdown、难懂内部枚举或明显中英混杂；
- 关注、变化水位、退出或重新登录产生错误账户状态。

### P2：记录后批量处理

- 文案、间距、排序等不阻断理解的体验问题；
- 当前范围明确不支持的拼写纠错、复杂模糊搜索或高级筛选；
- 内容不足但没有错误事实的公司页面。

## 8. 认证方式评估边界

当前基线继续使用邮箱验证码，并单独测量其摩擦。手机号验证码或微信扫码只有在以下条件确认后才进入独立认证 PR：

1. CloudBase 环境和目标地域支持；
2. 受邀手机号或微信能够唯一绑定已有本地用户，不产生重复账户；
3. 发送频控、验证码滥用防护、审计和费用上限已定义；
4. 用户仍须先获得本地邀请，登录方式不能绕过本地角色、基金授权和 RLS；
5. 保留邮箱方式作为恢复路径，避免单一身份源故障锁死账户。

### 8.1 首轮准入结论

2026-08-20 对现有 CloudBase 环境完成只读核验：环境位于上海，满足手机号验证码登录的地域条件；邮箱登录已启用；短信策略存在默认通道，当前单号码日上限为 30 次。手机号登录尚未在本项目中开启或编码，微信开放平台登录也未接入。

官方依据：[短信验证码登录](https://docs.cloudbase.net/authentication-v2/method/sms-login)、[账户关联登录](https://docs.cloudbase.net/authentication-v2/auth/account-linking)、[登录方式管理](https://docs.cloudbase.net/authentication-v2/auth/manage-login)和[CloudBase 价格文档](https://cloud.tencent.com/document/product/876/75213)。能调用短信接口不等于已经完成同账户绑定、费用保护或本地权限映射验收。

如果后续独立认证任务继续推进，优先顺序为“手机号验证码 V1，微信登录后置”。手机号 V1 必须：

- 仅向已有受邀账户开放，不借机开启公开注册；
- 先把手机号关联到原 CloudBase 账号，证明使用邮箱或手机号登录时返回同一稳定身份主体，不产生第二个本地用户；
- 保留邮箱作为邀请标识和恢复方式；
- 把单号码日上限从平台默认的 30 次收紧到邀请测试所需水平，并增加环境总量和费用保护；
- 手机号仅传给 CloudBase 身份服务，业务数据库首版不新增手机号字段；
- 通过真实账户验证 CloudBase 用户资料仍包含本平台当前授权映射需要的邮箱；如果不包含，必须先调整身份映射契约，不能按邮箱猜测合并账户。

微信登录需要额外的微信开放平台应用、回调和账号关联流程，当前不比手机号方案更小，也不应阻塞 M6A 内容价值验证。

## 9. M6A 交付物

- 固定公司样本清单；
- 两个自控个人账户的逐步测试记录；
- 逐公司内容评分表；
- P0/P1/P2 缺陷清单和证据；
- 登录摩擦、内容价值、证据质量和人工耗时基线；
- `可进入 M6B`、`修复后复测`、`先补内容生产` 或 `停止邀请` 的唯一结论；
- 下一项唯一最高价值工作。

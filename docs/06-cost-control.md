# 06 成本控制

E3 定期检查复用本节的公开研究预占与结算，默认 7 天、每批最多 5 公司；仍使用单任务最多 4 次搜索及原抓取上限。单组检索不意味着固定只需一次付费请求，回退/来源恢复仍计入同一任务。定期检查不消耗个人申请次数；与手动研究共享缓存和公司/系统预算。预览输出公司、Provider、次数上限、零模型 Token 和计划费用保守上界；未配置价格时保持未知。专用开关默认关闭，无实际调度安装。

> 本文公式是目标口径，不是当前账单。E2.2 已为业务公开研究与主体查证增加费用状态、持久化预占和结算；验证范围及结果见[实施看板](10-implementation-plan.md)。模型解读、机构可信来源及基础设施尚未接入本次金额预占，不能宣称所有 Provider 都受统一硬预算保护。历史零值不推断真实免费。

## 1. 变量与公式

目标参数进入版本化策略或价格配置，不写死在业务代码；当前以已有环境配置为主，不因公式需要提前建设完整策略表。

- `N`：公司数；`h/a/w/b`：高风险、近期活跃、关注、普通公司的互斥比例。
- `q`：经 TTL、冷却和任务合并后每月独立按需任务数。
- `f_h/f_a/f_w/f_b`：各组月检查频次；`k`：每任务计划搜索数。
- `c`：搜索缓存命中率；`d`：新文档命中率；`r_f`：规则过滤率。
- `t_in/t_out`：单次 LLM 平均输入/输出 Token；`r_review`：候选进入人工审核比例。
- `p_s/p_in/p_out/p_b`：搜索、百万输入/输出 Token、商业数据单价。
- `B`：商业数据调用数；`m`：单次审核分钟；`p_h`：人工小时成本。
- `C_compute/C_db/C_file`：计算、数据库、文件存储月成本。

公式：

```text
T_daily  = 30N
T_tiered = N(h*f_h + a*f_a + w*f_w + b*f_b)
T_demand = N(h*f_h + a*f_a + w*f_w) + q
S        = T * k * (1-c)
L        = S * d * (1-r_f)
TokenIn  = L * t_in; TokenOut = L * t_out
C_external = S*p_s + TokenIn/1e6*p_in + TokenOut/1e6*p_out + B*p_b
C_review   = L*r_review*m/60*p_h
C_total    = C_external + C_review + C_compute + C_db + C_file
C_company  = C_total/N
C_event    = (C_external + C_review)/reliable_published_events
```

`C_event` 在策略比较中使用可变成本，基础设施单独列示，避免固定成本掩盖更新策略效率；经营决策仍看 `C_total`。

## 2. 三种策略

| 策略 | 优点 | 主要代价 | 结论 |
| --- | --- | --- | --- |
| 每日全量 | 延迟最低、覆盖最宽 | 大量无变化任务、缓存失效与人工噪声；成本随 `30N` 增长 | Demo 不采用 |
| 分级定时 | 比全量节省，规则可解释 | 即使无人关注，普通公司仍固定扫描；命中率受周期限制 | 可作基线 |
| 按需+低频巡检 | 查询价值、风险和变化驱动；缓存/合并效果最好 | 需准确维护新鲜度与调度状态，低关注公司发现延迟更长 | 当前选择 |

选择第三种不是只看调用总数：目标函数是最低的可靠有效事件综合成本，同时满足关注公司时效。数据过期先返回旧快照；请求只在预算、TTL、冷却和去重后入队。高风险可临时升频，长期无变化自动降频。

## 4. 预算层级与闸门

预算按任务、公司日/周、租户周/月、系统周/月逐层校验，同时检查搜索数、输入/输出 Token、冷却期、查询缓存、内容哈希、Provider 开关和许可。费用未知时按配置上界预留；完成后结算实际或估算值。

```mermaid
flowchart TD
  A[准备更新任务] --> B{外部调用总开关开启?}
  B -- 否 --> X[仅返回已有数据并记录 disabled]
  B -- 是 --> C{许可和 Provider 已启用?}
  C -- 否 --> X
  C -- 是 --> D{缓存、哈希或冷却可跳过?}
  D -- 是 --> Y[复用缓存或合并任务]
  D -- 否 --> E[估算搜索、Token、商业数据和费用]
  E --> F{任务/公司/租户/系统预算均足够?}
  F -- 否 --> G[标记 budget_deferred 并保留查询]
  F -- 是 --> H{dry-run?}
  H -- 是 --> I[展示调用计划和估算，不执行]
  H -- 否 --> J[预留预算并调用]
  J --> K[记录实际用量、费用和有效产出]
```

## 5. R3 受限公开研究预算

下述四次搜索等上限针对业务研究阶段。身份阶段的独立上限及两阶段合计以 [ADR-0020](DECISIONS/ADR-0020-public-identity-research.md) 和现有配置为准，不重置旧消耗；E2 仅补计量与控制，不默默扩大额度。

R3 默认采用百度主源、博查条件回退，不并行双查。固定九类投资研究覆盖被压缩为两组高密度查询；每个任务最多 4 次搜索，其中回退调用也计入同一上限。默认路径在主源失败或没有主体准确、非资料页且未明确过期的结果时回退。启用 E4.2 的普通按需任务还允许该组候选正文全部读取失败后回退，沿用原查询且每组/供应商最多派发一次，替代额外的事件词回查；缓存和已结算失败可重放，不确定支出先暂停。单纯排名靠后不触发双查。系统默认搜索上限为 50 次/日、1500 次/月，每次最多取 10 个结果，再经过 12 个候选 URL、8 次抓取、3 份文档、2,000,000 字节和 180 秒执行时间的逐层限制。增量任务的时限从首次执行开始，跨 Worker 步骤不重置；每步及追加搜索/HTTP 派发前检查，在途请求按原超时结束。真实额度或价格变化只调整部署配置，不改业务代码。

搜索缓存默认 14 天，键包含 Provider、规范查询和公司身份指纹。同一公司被不同用户查询时复用平台共享缓存；公司身份变化或缓存过期后重新查询，质量/近期策略升级则复用搜索与文档缓存并重新过闸门，因此不为规则调整重复消耗搜索额度。页面刷新、断线重连、重复申请、取消后再次打开以及缓存命中均不增加搜索调用。取消时已取得且通过主体匹配的公共缓存继续保留，避免下一位用户重复付费，但用户当日防滥用次数不退。

V1 不调用模型、不生成报告，因此模型 Token 和模型费用恒为 0。搜索 API 即使当前免费，也视为“有额度或可能计费”的外部资源：专用 Worker 必须同时开启 `WEB_RESEARCH_ENABLED`、`EXTERNAL_CALLS_ENABLED`、`WEB_RESEARCH_CALLS_ENABLED` 和 `PAID_API_CALLS_ENABLED`；API/前端继续保持关闭。这样可以避免免费额度变化后在无人知情时继续消耗。

R3.5 仍不提高每任务四次搜索上限：原始来源回溯和证据缺口补查共享一个额外尝试名额，补查只调用百度主源，博查最多融合已有缓存。尝试状态在联网前写入 PostgreSQL，进程中断恢复不会重复消耗。候选模型解读与既有重要变化解读共用月 Token 上限；只有本次新建、主体已核验且证据允许展示的候选才排队。缓存重放、无变化、取消、低重要性、证据撤下、打开页面和未请求报告均为零模型调用。

### E2.2 实际接入的控制

`web_research_budget.py` 复用 `usage_ledger`。公开搜索与网页取证属于平台公共研究支出；原 `tenant_id` 只保留执行 Worker 的审计归属，不向申请人租户重复计费。`quota_scope=platform_web`、任务键和信用代码哈希标识公司；入库前的主体查证与入库后的业务研究共享公司及系统金额预算，两阶段的任务次数仍独立。机构租户预算不由这次平台预算替代。

| 费用状态 | 含义 |
| --- | --- |
| `unknown` | 尚无金额依据，金额为 `NULL`；不能将空值转为零 |
| `estimated` | 按本次预占时保存的版本化单价乘已确认调用量 |
| `actual` | 管理员凭回执/账单核对的金额，保留原状态、原因、操作者和时间 |
| `confirmed_free` | 明确配置单价为零、纯 Mock，或确认未调用；网页直取仅指 Provider API 费为零，不含基础设施 |

新增配置见[环境示例](../.env.example)：`WEB_RESEARCH_COST_VERSION` 与两个 `*_PRICE_PER_CALL`；单价空值为未知，明确免费才填 `0`。未知单价需填写正的 `WEB_RESEARCH_UNKNOWN_PRICE_UPPER_BOUND`。`WEB_RESEARCH_TASK_LIMIT`、`WEB_RESEARCH_COMPANY_DAILY_LIMIT/WEEKLY_LIMIT`、`WEB_RESEARCH_SYSTEM_WEEKLY_LIMIT/MONTHLY_LIMIT` 均为 CNY，最多六位小数，默认 `0`。配置文件不提供真实价格，也不授权支出；原外部调用开关和次数上限照旧。

调用前在 PostgreSQL 短事务内使用同一事务锁检查额度并写入 `reserved`，提交后才进入 `in_flight` 并调用。数据库锁不跨 HTTP；同一调用键不能重复派发。任务次数基线保留旧累计消耗，已知失败及新尝试分别计量；缓存不增加调用。任务次数、系统日/月搜索次数及任务/公司日周/系统周月金额同时校验，金额不明时预占保守上界。

日/月沿用 UTC 边界，周以 UTC 周一开始。未结算的预占跨周期继续占额，不能靠跨日、取消或重启释放。调用前取消释放未派发记录；已返回结果只释放未使用部分。租约过期后，`in_flight` 变为 `uncertain`，保留全部预占并暂停新调用；不能把超时当作零消费。账本、结果与进度在同一结果事务提交。

历史零金额原样保留为 `legacy/unknown`；相关窗口中存在无上界的旧费用时，阻止新计费调用，明确免费调用仍受次数约束。已核对且能归属公司的旧金额计入公司预算；无法归属公司的旧主体费用保守计入各公司的金额检查，直至退出相应时间窗口。任何历史费用确认都必须有凭据，不批量推断。

管理员可通过 `python -m scripts.reconcile_web_research_usage <usage_id>` 只读检查；明确带上 `--apply --calls <次数> --actual-cost <CNY金额> --reference <回执编号> --reason <核对原因>` 才结算。命令沿用 `WEB_RESEARCH_WORKER_USER_ID/WORKER_TENANT_ID`，只处理平台公开研究账本，不构造 Provider，也不要求开启外部调用。未知记录在核对前继续占额。费用已核对不代表丢失的正文已恢复：业务任务进入收尾并标注结果不完整，主体查证保持待核对状态，不从账单生成事实。

Worker 输出包含金额状态、已知金额小计、预占上界和不确定调用量；`dry-run` 输出配置与次数上界，不再把未知的计划费用写为零。迁移 `0030` 只增加上述字段/索引/RLS并允许未知金额；有新记账或精确费用后拒绝破坏性降级。回退先停 Worker 并保留账本，不退回旧的“先调用后记账”代码继续运行。

## 6. 敏感参数与观测

最敏感的参数通常是新文档命中率、缓存命中率、每任务搜索数、规则过滤率、人工审核比例/时长和关注/高风险公司比例。`usage_ledger` 必须同时记录无变化任务、候选数、发布数、误报、缓存命中和影子价格；已有订阅边际费用可设为 0，但仍应记录影子成本，便于未来迁移。

投资者变化解读使用独立月 Token 上限和逐次用量台账。无新变化、低于重要性门槛、重复输入、用户打开页面或用户未请求完整报告时均为零模型调用；真实 Worker 只有在专用开关、外部调用开关和可能计费开关同时开启，且已经填写当前输入/输出 Token 单价后才能运行。价格缺失或预算不足时关闭失败，不自动改用更贵模型。

Demo 新增支出目标为 0：默认开关关闭、预算为 0、使用 Mock 和既有本地资源。只有用户明确授权并填写价格配置后，外部调用预算才可大于 0。

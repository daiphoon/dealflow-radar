# 11 测试与验收策略

## 1. 原则

测试默认完全离线、确定性、使用虚构数据和 Mock Provider。任何外部集成测试必须显式设置 `RUN_EXTERNAL_TESTS=true`、单独标记、先显示 `dry-run` 费用且 CI 默认跳过；真实付费密钥不进入测试仓库。

测试层次：领域单元测试 → 数据库约束/迁移测试 → API 与 Worker 集成测试 → 最小浏览器闭环。优先测试会导致错误事实、越权、重复费用或错误发布的行为。

## 2. 必测规则

| 范围 | 核心用例 |
| --- | --- |
| 身份解析 | 信用代码/全称确定匹配；简称同名 unresolved；品牌不能单独发布严重负面 |
| 工商身份核验 | 政府/授权商业依据分离、域名和固定端点、信用代码校验位、文件/批次/缓存幂等、精确匹配、冲突不静默修改、过期/无关候选拒绝 |
| 身份认证 | CloudBase 固定网关和邮箱身份源；手机号默认关闭且只允许同一已绑定 `subject`；Demo Header 在正式模式无效；唯一邀请绑定；重复邮箱/停用账户拒绝；刷新、退出、审计和本地角色不受 Provider group 影响 |
| 文档幂等 | 同外部 ID、规范 URL、内容哈希重复运行不新增；URL 内容变更保留版本 |
| 人工导入 | 仅私有目录 JSON；大小/版本/许可/时间精度校验；文件与批次幂等；未解析主体进入身份审核但不生成事件 |
| 事件去重 | 同事件多来源只新增证据；指纹版本可追踪 |
| 事件 Schema | 枚举、评分范围、金额/币种配对、额外字段、未知值和时区校验 |
| 发布路由 | 安全 A/B 来源自动发布；链接未检查/失效、低置信度及高/极高风险只形成未确认线索；策略版本和原因可追溯 |
| URL 验证 | 外部开关关闭时零网络；开启后限制每批次数；拒绝回环/私网；保存 HTTP 状态和最终 URL |
| 审核状态 | 只有身份歧义默认创建新人工任务；既有驳回/纠错/撤回保留历史和理由 |
| 预算闸门 | 总开关、任务/公司/租户/系统预算、`dry-run`、超限延迟 |
| 调度 | TTL、升降频、冷却、相同公司任务合并、租约过期恢复 |
| 按需研究队列 | 同步提交零外部调用、身份确认前零公司创建、10/日与30/月双限额、临时提额到期、同公司任务复用、取消阶段语义、零调用只退月额度、断线恢复、完整缓存先于预算闸门、供应商900/日与9000/月闸门、跨任务限速、旧私有公司不静默晋升且不对个人泄露 |
| 无变化路径 | 内容哈希不变时 LLM 和报告重建调用数为 0 |
| 权限隔离 | 跨租户、无基金授权、顾问过期授权、公共快照泄露私密字段均拒绝 |
| 双通道查询 | 无基金用户精确搜索/详情；私有公司、别名、文档、提及、投资和线索不可见；基金叠加层保持可用 |
| 个人回访 | 首次建基线；只返回未看过的已发布共享事件；重复查看幂等；不同用户独立；私有候选不进入变化 |
| 个人报告 | 只读共享事实和允许展示的证据引用；投资/私有文档/线索不进入正文；幂等、月上限、owner 隔离和零 Provider/模型调用 |
| 共享事实晋升 | 私有来源不变、独立共享 ID、同源幂等、跨机构同事实复用、证据展示引用与原文隔离、资格拒绝、撤回隐藏和追加式审计 |
| 财务指标 | 来源性质必填、单位/期间不可比不算同比、未知显示固定文案 |
| 迁移 | 空库升级、逐版升级、约束/索引/RLS 存在、迁移不可修改历史 |
| 生产部署基线 | 正式模式配置失败关闭、应用容器非 root、边缘代理最小能力、数据库 readiness、伪造 Demo Header 拒绝、Compose 可解析、生产镜像可构建、备份可读且可恢复到隔离库 |
| 最小闭环 | Mock 历史审核与人工导入自动路由、快照、未确认线索、页面、证据和用量均可复现 |

## 3. Provider 合约测试

每个 Provider 对同一合约 fixture 验证：稳定请求/响应版本；超时和错误映射；缓存标志；外部记录 ID；许可元数据；Token/费用估算；重试上限；禁用状态不产生网络。Mock 实现必须可注入成功、无变化、限流、Schema 错误、主体歧义和严重负面场景。

天眼查适配器还必须验证：输入在联网前完成校验；只允许固定 Core 端点和身份/六模块批准工具；不跟随重定向；400 不重试、429/5xx 最多重试一次；响应大小和 JSON Schema 失败关闭；名称候选必须由唯一信用代码锚定；研究响应中的信用代码冲突不入库；私有缓存命中时零网络且事实哈希稳定；业务数据库不出现完整供应商原始响应或联系方式；真实 10 家验证标记为外部测试并默认跳过。

按需单公司研究另验证：名称搜索只有唯一精确工商全称和单一信用代码时才接受，否则要求用户补充信用代码；API 提交和状态轮询不直接实例化 Provider；Worker 未同时开启按需、外部和相应天眼查专用开关时失败关闭；付费、自动刷新、自动发布和可信来源开关必须保持关闭；平台调用量汇总覆盖所有天眼查操作。六模块测试必须覆盖逐项状态、无可靠数据、预算延迟、模块失败后继续、取消后停止后续模块、不同时间重复响应去重、完整缓存零外部调用、已核实事实/平台待核实线索分层、零模型和零报告。还要在真实 PostgreSQL 事务中验证 `commit/rollback` 后 RLS 上下文重绑、个人取消无需全局任务更新权限、系统受限原始资料和机构私有字段不被其他用户读取，以及单 Worker 相邻任务仍保持最小请求间隔。CI 只用 Mock 响应，不使用真实 Key、网络或现有 10 家样本。

CloudBase 身份适配器默认使用 `httpx.MockTransport` 验证固定环境网关、无重定向、超时和响应大小、active 状态、邮箱/手机号验证码登录、refresh token 轮换和退出。手机号测试还覆盖默认关闭、格式标准化、冷却和日总量、账户存在性不泄露、同一 `subject` 复用、未绑定 `subject` 禁止按邮箱首次关联，以及不把完整手机号写入本地数据。集成测试继续覆盖伪造 Demo Header、无邀请、跨 tenant 重复邮箱、停用 user/tenant、本地角色和认证审计；CI 不得向真实邮箱或手机号发送验证码。真实环境收码只在项目负责人明确绑定既有账户并启用开关后执行。

## 4. 安全与隐私测试

至少构造两个租户、两个基金和交叉持有同一虚构公司的数据。直接数据库查询、API 列表、详情、导出、审核和后台 Worker 都执行负向授权测试。日志快照扫描 API Key 形态、密码、Cookie、完整私密文档和未脱敏金额；导入文件测试宏文件、超大文件、路径穿越和恶意 Prompt 文本只被当作数据。

认证安全测试还要确认 access/refresh token 不进入 URL、数据库、日志或 Git；认证审计只能由本人追加和读取、同 tenant 平台管理员只读，跨 tenant 不可见且应用角色不能更新或删除。CloudBase group、前端字段和 Demo Header 都不能替代本地角色、基金授权或 RLS。

## 5. 第 1 阶段文档验收

- 文件清单、ADR 数量和 Mermaid 图数量符合要求。
- `AGENTS.md` 与附件指定区块一致，且无嵌套 `AGENTS.md`。
- Markdown 本地链接目标存在；无重复一级标题和冲突的枚举/默认开关。
- 检索疑似密钥、真实公司/基金私密字段和误开启外部调用的配置。
- 成本表按公开公式本地复算；不访问网络。
- `docker-compose.yml` 仅为 PostgreSQL 草案且未启动。

## 5.1 M6A 人工产品验收

自动测试证明权限规则和确定性行为，不证明真实内容对投资者有价值，也不证明页面无需指导即可理解。M6A 使用[创始人自测手册](13-m6a-founder-validation-playbook.md)和[测试记录模板](templates/m6a-test-session.md)，对固定 10—12 家真实共享公司执行登录、搜索、详情、证据、关注、变化和报告测试。

项目负责人控制的多个邮箱只验证账户隔离和首次登录，不计作多名独立用户。M6A 记录原始耗时、失败、人工帮助和内容判断；不得修改样本或放宽共享标准以使指标通过。出现主体错配、私有泄露、无证据事实、撤回事实仍展示或意外自动发布时立即停止。M6A 只能决定是否进入 M6B，不能替代独立邀请用户反馈，也不能单独证明具备公开上线条件。

## 6. 第 2 阶段验收命令

```bash
uv run ruff check backend migrations scripts tests
uv run pytest -q
DATABASE_URL=sqlite:////tmp/dealflow_radar.db uv run alembic upgrade head
POSTGRES_RLS_DATABASE_URL='postgresql+psycopg://受限应用账户:本地密码@127.0.0.1:5432/equity_radar' uv run pytest -q tests/integration/test_postgres_rls.py
cd frontend
npm audit
npm run typecheck
npm run build
```

当前自动测试覆盖严格事件 Schema、Mock 合约、空库迁移往返、PostgreSQL DDL/RLS 编译、文档/事件幂等、历史人工审核发布、证据与快照、基金隔离、同步查询零 Provider 调用、配置化 TTL/冷却和刷新任务合并。双通道、身份索引与晋升测试额外覆盖信用代码/当前全称/已核实曾用法定名称精确搜索并返回同一公司 ID、无结果零写入、无基金共享详情、租户私有曾用名及其他私有别名/文档/提及不参与跨 owner 搜索、个人与机构未确认线索隔离、两个基金各自投资叠加、独立共享事实、同源及跨机构去重、资格闸门、未检查链接警告、撤回、审计和私有原文保留。M4 额外覆盖查询/关注/申请/报告服务端上限、重复关注和申请幂等、无结果不建公司、首次查看基线、新共享事件逐条回执、重复查看幂等、个人状态与报告跨用户不可见、私有文档/候选/投资不进入报告、用户明确提交的申请仅平台管理员可跨租户处理，以及所有动作外部调用、模型 Token 和自动发布为 0。真实 PostgreSQL RLS 测试默认跳过，显式提供受限账户 URL 后验证账户非所有者/非超级用户/无 `BYPASSRLS`、受保护表启用 RLS，以及无上下文、跨租户、伪造租户上下文、跨基金、无授权、跨 owner、普通审核员共享写入拒绝和审计不可变；测试数据在同一事务中回滚，可重复执行。

GitHub CI 使用单个、10 分钟上限的 Ubuntu Job 和临时 PostgreSQL 16 服务，在 Pull Request 与 `main` 推送时运行 Ruff、格式检查、SQLite 迁移升级/漂移/降级、完整 Pytest（含受限账户 RLS）、TypeScript 和前端生产构建。M5A 进一步校验生产 Compose、实际构建后端/前端生产镜像，并在无网络业务调用、无真实 Secret 的虚构配置下执行生产预检。M5B 前置测试还校验单机 Compose 可解析、备份工具镜像可构建、强制加密失败关闭、明文 COS 上传拒绝、COSCLI 配置权限和恢复私钥挂载边界。CI 使用固定虚构数据和临时数据库凭据，不读取仓库 Secret，业务外部调用开关全部关闭；CI 不能证明真实域名、证书签发、云主机防火墙、真实 COS 权限/生命周期、异机下载恢复、告警送达或 CloudBase 四类真实账户已经通过，这些属于 M5B 人工验收。

受控来源监测额外覆盖：HTTPS/域名允许列表、localhost/私网/元数据地址、DNS rebinding、实际对端不匹配、跨域及超限重定向、robots.txt、MIME/可执行文件、超时/重试/大小上限、ETag/304/内容哈希、列表路径、RSS/Sitemap、候选幂等与版本、零网络 dry-run、双开关、RLS 和跨 tenant 负向访问。真实网站验证必须人工显式开启且不进入 CI；CI 只使用 `httpx.MockTransport` 和本地 fixture，付费调用、模型 Token 与自动发布均为 0。

可重复内容生产额外覆盖：候选必须先标记值得研究；身份歧义、失效链接和 `unclear/restricted` 许可失败关闭；交接后原候选/来源/owner 不变；文档、提及、证据与私有候选具有同 tenant 血缘；重复提交幂等；另一 tenant 和个人用户不可读取；`public_access` 可做私有研究但不能晋升，`permission_confirmed` 仍须独立人工晋升；整个交接外部调用、Token 和自动发布为 0。到期调度测试覆盖默认 dry-run、四开关、每次上限、活动任务合并、应检查时间幂等、连续失败退避和 Worker 过期租约恢复。

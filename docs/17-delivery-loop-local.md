## 剩余边界与下一次真实验收（本轮不执行）

1. 首要是重新授权独立真实样本与费用。先固定样本、业务答案及 80% 目标，研究输入只有已确认身份；记录代码/迁移/配置、完整 Provider 响应、候选延后原因及各阶段哈希。维护组与 discovery 组分别统计；第四家不能从分母删除。运行后逐项核对主体、金额/轮次、发生时间精度、IPO 指定阶段、来源/去重及授权展示。
2. 沿用现场配置硬上限，不自行扩大：每任务至多 4 搜索、8 网页请求、3 模型调用，模型单次输入 16000/output 2000、任务时长 180 秒。按封存单价 2/8 元每百万 token 算，模型保守上界 0.144 元/公司、四家 0.576 元；这**不含**搜索/专业正文积分。封存 Tavily 计价为 advanced 搜索/正文预占各 2 credits，但当前套餐和余额未重新核对，必须在 dry-run 中展示各 Provider 分配、积分和现金总上界，经批准后才派发。失败或未知结算不自动重试。
3. 复杂角色、含多笔融资的同一长句、缺锚点的 IPO 自然新闻仍可能被保守拒绝或拆成疑似重复；需要独立封存样本与真实模型对照，不能继续凭四家答案写特殊分支。专业 Provider 的语法/来源取得能力仍需受控实测。常规申请保持 discovery 默认；maintenance 由受控任务输入显式设置，本轮没有新增用户切换入口。
4. 当前“已读”机制按 event_id，只针对已确认事件，不能完整识别同一 ID 的实质版本更新。最小后置方案是按有效事实集合产生用户可见版本摘要，已读回执增加该版本；纯补源不改变版本。涉及回执迁移和产品语义，本轮未启用推送或擅自扩大行为。
5. 无新增迁移，旧 JSON 只读兼容；处理版本升级记录新观测。若以后上线再回退，应先停新处理并备份，保留新历史，验证旧读取器对角色日期/阶段关系/部分结果的降级显示，不删除记录或倒改 0035。

# M2-R：受限研究结果与未完成状态如实交付

本工程候选修复网络能力预检、八类研究完成状态和报告表达。M1 已按既有最终回执关闭；上一轮 M2 仍是 `PARTIAL / FAIL`、严格召回 `0/8`，九家公司已消耗，不能再称为新留出。没有重跑研究、降低分母或改原回执。

## 当前网络证据

先于产品修改，对 `example.com`、`www.python.org`、`www.iana.org` 在 Mac、本地 Docker、香港作同目标诊断。当前 Mac/Docker 返回 `198.18/15` 非公网地址，安全链在 HTTP 前拒绝；香港返回公网地址，诊断 TLS 与 peer 对应关系通过。

这是当前观察，强烈支持宿主 DNS/代理影响 Docker 的解释；具体组件仍未识别。上一轮原日志只有 `blocked_network`，没有实际地址，历史根因继续未知。最后的香港候选正式预检证据与精确 head/CI 一起封存在统一私有交付包，不用普通 HEAD 连通性代替正式 Fetcher。

同候选正式路径结果：Mac/Docker 均在 HTTP 前拒绝（0 次），香港为 `HONG_KONG_RESEARCH_NETWORK_READY`，6 次 HTTP、60,188 字节、TLS 与 peer 均 6/6。短命容器及临时来源目录已清理；没有 Provider、模型、数据库或生产配置挂载。

## 用户更新与完成状态

主动更新的 `bounded_full_scope_refresh` 计划八类：融资股权、退出流动性、司法合规、财务经营、合同商业、产品技术、治理人员、产能资产。每类分别完成、部分完成、失败、预算暂缓或未执行；八类均完成有限检查才整体 complete。

默认预算仍为 4 次搜索、8 次 HTTP、2MB、3 份正文、3 次模型、每次 16k 输入/2k 输出、180 秒。四次搜索不足以保证八类完成；未执行项直接展示，不追加调用求通过。按最近尝试轮换起点，正文按现有类别轮转，不根据旧基准优先某类。

Watchlist 仍是有限低成本检查且保持关闭。每类成功检查时间、用户状态和整体判断复用同一 completion 投影；缓存不冒充刚查过，失败不更新成功时间。冻结旧两主题任务仍按旧计划恢复，不能冒充新八类完整任务。

## 网络预检与许可

`research-network-v1` 在任何计量 Provider 前执行，包含 identity 研究入口。非公网、混合地址、无法验证 peer、rebinding、私网 redirect 等继续 fail closed；没有 fake-IP 白名单、平台特例或私网访问。固定检查最多 12 HTTP/256KB，不构造 Provider、不连接数据库、不存正文；成功在同一进程最多复用五分钟。

失败不进入计量 stage、不扣未使用研究额度。已有资料仍可生成固定模板，但明确“本次研究未开始/环境预检失败”。失败审计保存安全元数据，用户只见抽象类别，不输出基础设施和认证细节。

## 报告与维护

新 `personal-company-v4` 显示本次状态与八类范围，分别呈现近期确认资料、窗口外历史、获准未确认线索和缺口。全部有限检查完成但无达标事项，与未检查、正文失败、预算延期、信息不公开分别表达。生成/读取/重试/同内容复用和撤权保护均通过正式 API 验证，旧 v3 不重建。

lead 仅在现有权限允许时显示；不会发布、提置信度或进入正式快照。已有 JSON 保存 v4 lead 引用类型，独立读取时重新核验撤回/许可，API 保持 UUID 列表，无迁移。

正式 curated preview/apply 的虚构维护验证覆盖补证、日期补强、确认候选、纠正、新阶段与不同事项；旧 RawDocument/Observation 内容保留、版本和重复幂等检查。待核表不能通过说明文字自动晋升，跨阶段的新记录仍由负责人提供稳定 ID；这些入口限制如实列入交付包，不用手工写表伪造成功。

验证包括网络安全矩阵、八类正常任务及旧计划兼容、巡检失败时间、十四类报告 SQLite/PostgreSQL/RLS、正式维护、旧九家封存副本离线回归、前端、迁移、Compose 和 Docker。精确通过/跳过数量、失败轮修正说明、PR/head/tree、真实 Verify 及完整渲染报告均以统一 `M2-R Research Completion & Truthful Delivery Package` 为准。

本地完成和远端 CI 不等于已经合并或部署。通过全部工程与网络门槛后，只能建议另行批准下一批全新留出集价值复测；不能自动建立样本、部署、研究、巡检或开启 M3。

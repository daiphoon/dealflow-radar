# 07 权限、安全与合规

## 1. 数据分级

| 等级 | 示例 | 默认控制 |
| --- | --- | --- |
| 公开来源事实 | 官方公告、公开新闻元数据 | 私有平台授权用户可复用；仍受来源许可限制 |
| 机构内部 | 机构标签、审核意见、内部关注状态 | 仅同租户授权角色 |
| 基金敏感 | 投资金额、持股、估值、MOIC、TVPI、协议条款 | 租户+基金授权、字段级脱敏、读写审计 |
| 高敏文件 | 未公开财报、投委会、董事会、季度报告 | 最小授权、独立存储引用、禁止日志与 Git |
| Secret | API Key、密码、Cookie、加密密钥 | Secret 管理器/环境注入；永不入库明文或日志 |

Demo 只使用虚构公司和基金，不放入真实水印、投资人身份或个人标识。

## 2. 角色与授权

预置角色：机构管理员、基金管理员、投资人、专业顾问、审核员、只读用户。权限由动作和范围组成，不以角色名硬编码业务逻辑。

- 机构管理员：管理本租户用户、基金授权和预算，不自动获得高敏文件全文权限。
- 基金管理员：管理被授权基金的投资数据和成员。
- 投资人：读取被授权基金与关联公司信息。
- 专业顾问：仅访问任务明确授权的公司、资料和时间窗。
- 审核员：查看必要证据并作发布决定；私密投资字段需额外基金授权。
- 只读用户：只读授予范围，不能更新、导入或审核。

同一用户通过 `fund_access_grants` 访问多个基金；同一公司可连接多个基金，但不能借由公司公共页推断其他基金持仓。

## 3. `visibility_scope` 与 RLS

范围值为 `public`、`tenant`、`fund`、`user`、`system`。`public` 仅表示平台内共享事实，不表示匿名互联网公开。访问判定顺序：认证用户 → tenant 状态 → 行范围 → 基金授权/owner → 动作权限 → 字段遮罩。PostgreSQL RLS 使用请求事务内的 tenant/user 上下文；后台 Worker 使用受限服务身份并显式携带任务范围，禁止使用绕过 RLS 的日常应用账户。

公开快照构建器只读公开事件/指标；基金投资概览在响应层按授权单独拼装，不能缓存为全局公司快照。

## 4. 敏感操作审计

记录登录、授权变更、私密记录读写、导入/导出、审核决定、事件纠正撤回、预算变更、Secret 引用变更和删除请求。日志保存 actor、时间、对象 ID、动作、结果、请求关联 ID和敏感类别，不保存完整私密正文、凭据或不必要个人信息。审计日志追加写并设置防篡改备份策略。

## 5. 文件、密钥与日志

- `data/private/`、备份、真实报告和本地 Secret 均被 `.gitignore` 排除。
- 数据库只存文件哈希、许可和 `StorageProvider` 引用；生产存储需服务端加密和最小 IAM。
- API Key 通过部署 Secret 或环境变量注入，界面只显示末四位或引用名。
- 结构化日志对邮箱、证件、URL 查询参数和业务金额按策略脱敏；异常堆栈不得包含请求正文。
- 导出文件带访问者、范围和过期时间；高敏下载使用一次性授权并记录审计。

## 6. 备份、恢复、删除与保留

PostgreSQL 与许可允许的文件分别备份，备份加密且与主机隔离；定期做恢复演练。Demo 的建议目标为 RPO 24 小时、RTO 8 小时，仅为规划值而非 SLA。恢复后校验租户/RLS、事件证据关联、文件哈希和任务租约。

用户删除请求区分账号、租户私密数据和有合法保留义务的审计/公开事实。可删除内容先撤销访问，再按租户政策异步清除；共享公开事实不因单一基金退出而删除，但需响应来源撤回、许可到期和事实纠正。审计记录保留最小必要标识并遵循法律/合同期限。具体操作见[运维手册](12-operations-runbook.md)。

## 7. 专业顾问升级流程

1. 用户提交问题、目标公司和期望范围，形成私有任务单。
2. 管理员确认申请人基金权限、可用内部资料、价格和响应时间。
3. 顾问获得最小、限时、可审计访问；默认不能浏览同租户其他基金。
4. 研究区分引用事实与顾问分析，分析不写入事实字段。
5. 报告默认 `visibility_scope=user` 或 `fund`，导出受控。
6. 若要沉淀公共事件，必须去除投资/个人信息，确认来源许可，重新完成身份、去重、证据和审核流程。

本流程只做预留，当前不实现任务单、收费或顾问门户。

## 8. 主要威胁与控制

| 威胁 | 首要控制 |
| --- | --- |
| 跨租户/跨基金越权 | RLS、基金授权、负向权限测试、审计 |
| 研究文件含恶意内容 | 类型/大小限制、隔离解析、禁宏、文本化后再处理 |
| Prompt 注入影响事实 | 外部文本视为数据、严格 Schema、证据定位、风险闸门 |
| Secret 泄漏 | Secret 引用、日志脱敏、扫描、快速轮换 |
| 来源许可违规 | 来源级许可字段、保留策略、Provider 白名单 |
| 严重负面误报 | 身份解析、双来源规则、强制人工审核、纠错撤回 |

本设计不是法律意见；进入真实数据验证前需由实际运营主体确认适用的数据、版权、网络安全和基金保密义务。

# 07 权限、安全与合规

## 受控来源网络边界

真实来源检查只在独立 Worker 中运行，并由 `EXTERNAL_CALLS_ENABLED` 与 `TRUSTED_SOURCE_CALLS_ENABLED` 双开关控制。URL 仅允许 HTTPS 和已登记根域名；拒绝 userinfo、localhost、IP 直连、回环、私网、链路本地、云元数据及其他非公网解析结果。每次请求与每次重定向都重新校验域名和 DNS，实际连接对端必须与预检公网地址一致，以阻断 DNS rebinding 与重定向绕过。

Worker 遵守 robots.txt，使用明确 User-Agent，不登录、不提交表单、不保留 Cookie；按运行限制请求数、总下载字节、单响应大小、超时、重试、重定向和域名访问间隔，并只接受预期 HTML/XML/Feed MIME。可执行文件、归档和非预期二进制内容安全失败。来源、运行和候选保持 tenant 私有，个人及其他 tenant 不可通过 API、数量或字段读取；成为共享事实仍需走独立人工晋升流程。

到期调度器默认 dry-run，实际入队要求总外部调用、可信来源、自动刷新和独立调度四个开关同时显式开启，且付费调用和自动发布必须保持关闭。调度幂等键包含来源和应检查时间，连续失败只延长下次到期时间，不放宽网络安全规则。

候选研究交接同时要求本 tenant 的 `platform_admin` 和 `institution_admin`；入参不能改写候选的公司、来源、URL 或 owner。数据库通过 `(candidate_document_id, owner_tenant_id)` 复合外键和每候选唯一交接约束，阻止跨 tenant 关联和重复私有底稿。原候选和来源不变，新文档、提及、事件与证据均为 `organization_private`；共享仍需独立审核。

## 授权商业工商数据边界

天眼查身份 V1 是已授权商业聚合数据，不是政府登记机关来源。数据库和界面必须保留 `licensed_business_data` 标识，不得显示为“政府官方来源”。真实调用只在 `EXTERNAL_CALLS_ENABLED` 与 `TIANYANCHA_IDENTITY_CALLS_ENABLED` 双开关的一次性本机窗口中运行，固定 Core 端点和批准工具，不跟随重定向；同步用户请求、自动刷新和自动发布均不得触发。

完整供应商响应可能包含本里程碑不需要的联系方式，只能存入 Git 忽略、目录 `700`、文件 `600` 的私有缓存。业务库只保留工商全称、信用代码、地区、登记状态、登记机关、数据时间、来源 ID 和响应哈希。API Key 只由环境或 Secret 注入，不进入数据库、Git、响应和日志。身份核验不能替代事件证据，也不能降低严重负面事实的审核和多来源要求。

## 1. 数据分级

| 等级 | 示例 | 默认控制 |
| --- | --- | --- |
| 平台共享事实 | 已核实工商身份、已审核事件、许可允许展示的证据引用 | 登录且有有效权益的平台用户可复用；不表示匿名互联网公开 |
| 个人私有 | 个人关注、备注、上传资料和个人未确认线索 | 仅 `owner_user_id` 对应用户 |
| 机构内部 | 机构标签、审核意见、内部关注状态 | 仅同租户授权角色 |
| 基金敏感 | 投资金额、持股、估值、MOIC、TVPI、协议条款 | 租户+基金授权、字段级脱敏、读写审计 |
| 高敏文件 | 未公开财报、投委会、董事会、季度报告 | 最小授权、独立存储引用、禁止日志与 Git |
| Secret | API Key、密码、Cookie、加密密钥 | Secret 管理器/环境注入；永不入库明文或日志 |
| 互联网匿名公开 | 无需登录即可访问的内容 | 本阶段默认关闭，不由 `platform_shared` 自动产生 |

公开 Demo 只使用虚构公司和基金。受控影子验证可以使用真实公开公司身份和公开来源，但不得放入真实投资金额、持股、内部估值、投资人身份或未授权资料。

## CloudBase 身份认证边界

CloudBase 只核验登录身份，不承载 PostgreSQL 数据、tenant、基金、角色、RLS 或业务权限。正式模式由 `AUTH_PROVIDER=cloudbase` 显式启用；FastAPI 随后完全忽略 `X-Demo-User-Id`。首次绑定只允许发生在刚完成邮箱验证码交换的登录请求中；普通 Bearer 请求和 token 刷新只能按已经绑定的 CloudBase subject 加载 active 本地用户。CloudBase 返回的 group、前端 Cookie 和界面隐藏均不能授予业务权限。

邮箱验证码固定使用邀请制 `target=USER`；CloudBase 账户和本地用户必须均已预先创建。`/user/me` 的 active 状态、subject 和顶层邮箱是身份映射输入；原生邮箱账户的 `providers` 不是可靠的第三方身份源列表，不作为首次绑定的独立证明。跨 tenant 重复邮箱、无本地邀请、用户或 tenant 停用、subject 冲突都失败关闭。access/refresh token 只进入 Next.js 服务端的 `HttpOnly + SameSite=Strict` Cookie，生产环境加 `Secure`；不得写入 URL、数据库、日志或 Git。认证审计只保存 subject 哈希并追加记录身份绑定、开始、刷新和退出。

CloudBase 身份请求是登录基础设施调用，不受业务数据 `EXTERNAL_CALLS_ENABLED` 开关控制；它也不能触发天眼查、搜索、模型、自动刷新或自动发布。默认 `AUTH_PROVIDER=demo` 只用于本地和 CI；对外环境禁止通过 Demo Header 回退。CloudBase 要求图片验证码时 V1 失败关闭，不绕过安全挑战。

## M5B 单机与备份安全边界

邀请测试的 PostgreSQL 可以与应用部署在同一主机，但只能位于内部 Compose 网络，不发布 `5432`。这会形成单机故障域，因此本机快照不能充当唯一备份。生产备份必须使用 PostgreSQL 自定义格式并先完成可读性检查，再以 `age` 公钥进行客户端加密；加密失败时不得产生可供上传的最终文件，临时明文必须清理。

生产服务器只持有加密公钥。解密私钥离线保管，恢复时只从 `/run/secrets` 临时只读挂载，不能进入服务器长期文件、COS、Git、环境变量、日志或命令参数。COSCLI 配置必须由项目负责人单独创建，文件权限不得宽于 `0600`，凭据只允许访问指定私有桶和备份前缀；上传脚本拒绝明文备份。腾讯云提供的服务端加密可作为第二层保护，但不能替代客户端加密和离线私钥。

M5B 依据 ADR-0014 使用腾讯云中国香港服务器，不以个人 ICP 备案作为上线依据，也不接入中国大陆 CDN。该环境只服务邀请制 MVP，不构成收费、投资建议或经营性互联网服务许可。邀请前必须提供最小隐私与测试说明，并默认不上传真实基金敏感资料。未来迁入中国大陆和正式收费前，必须成立并确认经营主体，完成企业 ICP 备案，并重新审查隐私、数据来源展示、经营许可和收费合规。

## 2. 角色与授权

当前预置角色为平台管理员、机构管理员、基金管理员、投资人、专业顾问、审核员和只读用户。目标个人通道以用户所有权和有效个人权益授权，不要求创建虚假机构角色。权限由动作和范围组成，不以角色名硬编码业务逻辑。

- 平台管理员：跨租户只读符合条件的私有候选和必要证据元数据，执行平台共享事实的晋升、拒绝和撤回；不得读取 `system_restricted`，也不能借此修改私有来源记录。
- 机构管理员：管理本租户用户、基金授权和预算，不自动获得高敏文件全文权限。
- 基金管理员：管理被授权基金的投资数据和成员。
- 投资人：读取被授权基金与关联公司信息。
- 专业顾问：仅访问任务明确授权的公司、资料和时间窗。
- 审核员：处理身份例外及按需纠错/撤回；私密投资字段需额外基金授权。
- 只读用户：只读授予范围，不能更新、导入或审核。

同一用户通过 `fund_access_grants` 访问多个基金；同一公司可连接多个个人、机构和基金，但不能借由共享公司页推断其他客户的关注、持仓或私有线索。`fund_access_grants` 只授权基金私有层，不授权平台共享公司档案。

公司主档和基金资产必须分离：已核验全局公司及其当前/曾用法定名称可被所有具备平台访问资格的用户复用，基金只通过 `investments` 叠加私有关系。只有显式身份确认产生的法定曾用名可进入共享索引；租户私有别名、内部代号、品牌名和未核实名称继续受 owner 与 RLS 约束。共享公司身份不提升事件、证据引用或原始文档的作用域。

## 3. `visibility_scope` 与 RLS

领域作用域为 `platform_shared`、`personal_private`、`organization_private` 和 `system_restricted`。别名、文档、提及、事件、证据引用和快照已使用这些值；公司、基金和投资关系仍保留 `public`、`tenant`、`fund` 兼容值。其中公司 `public` 只表示允许映射到平台共享目录，仍要求登录，不表示匿名互联网公开。

访问判定顺序为：登录用户 → 有效个人或机构权益 → 记录作用域 → owner/机构关系 → 资源授权 → 动作权限 → 字段遮罩。平台共享档案读取要求有效个人权益或任一有效机构权益；个人私有数据要求当前用户为 owner；机构私有数据要求机构关系、机构权益、资源授权和动作权限同时有效。PostgreSQL RLS 使用请求事务内的 tenant/user 上下文；后台 Worker 使用受限服务身份并显式携带任务范围，禁止使用绕过 RLS 的日常应用账户。

共享快照构建器只读平台共享事件和指标；基金投资概览及个人/机构私有数据在响应层按授权单独拼装，不能缓存为全局公司快照。没有基金授权但具有有效共享档案权益的用户仍可读取共享基础层。

当前 27 张表已启用 RLS：原有基金、导入、审核、任务和用量表，`companies`、`company_aliases`、`raw_documents`、`entity_mentions`、`events`、`event_evidence`、`company_snapshots`、两张共享决定审计表、`trusted_sources`、`source_check_runs`、`candidate_documents`、认证审计表，以及 `personal_watchlist_items`、`personal_company_requests`、`personal_usage_records`、`personal_company_view_states`、`personal_event_view_receipts`和 `personal_company_reports`。API 或本机导入命令在事务中设置用户和租户上下文；共享行要求 active 登录用户，个人行要求当前用户为 owner，机构行要求同 tenant 并满足角色或基金公司授权，`system_restricted` 不向普通应用用户或平台管理员开放。个人关注、用量、查看状态、事件回执和报告只允许本人读取；报告和事件回执只追加，不允许应用角色更新或删除。收录/更新申请因为由用户明确提交给平台处理，平台管理员可以跨租户读取和更新状态，但看不到该用户的关注或其他个人用量。共享事件和共享证据引用只有平台管理员可写；共享决定审计表只允许平台管理员读取和追加。认证审计允许本人追加和读取、同 tenant 平台管理员读取，没有更新或删除策略。私有别名、外部文档记录和文档去重键按 owner 分区唯一，避免不同客户因同名或同一来源记录相互阻塞。SQLite 只验证应用层过滤，不能替代 PostgreSQL RLS 负向测试。

当前 CloudBase 认证只替换身份凭证，个人订阅与机构赞助权益尚未实现；M3 完成真实收码和四角色验收前仍只适合本地或受控邀请验证。迁移账户仍可作为表所有者绕过策略，必须继续与日常 `NOBYPASSRLS` 应用账户分离。

## 4. 事件、证据与原始文档授权

- 事件事实、证据引用和原始文档资产分别保存作用域、许可和展示规则；任一对象共享都不会自动提升另外两个对象的权限。
- 平台共享事件只展示许可允许的来源名称、URL、日期、检查状态和短摘录。
- 付费数据、许可受限内容、网页全文和客户上传资料继续受独立授权与保留规则控制。
- 私有资料是唯一证据且未获得事实复用权时，事件不得晋升为平台共享。
- 文档许可到期、撤回或证据失效时，重新评估事件共享资格。
- 尚未检查的合法 HTTP(S) 链接只有在管理员显式确认后可晋升，并向个人用户显示“尚未自动验证”；已失效、不安全或许可受限的链接不得晋升或直接开放。
- 受控晋升固定为“私有候选 → 独立共享事件 → 安全展示引用”；`source_event_evidence_id` 和追加式决定日志保留反向血缘，私有 `raw_document_id` 不复制到共享引用。

## 5. 防枚举和响应隔离

- 搜索索引、结果总数和建议词只包含当前用户有权访问的平台共享目录。
- 不存在与无权访问的私有对象使用不可区分的响应，避免泄露私有记录存在性。
- 私有字段必须在服务端授权后才拼装，不得先返回再依赖前端 CSS 隐藏。
- 缓存键包含访问作用域和授权上下文；不得把个人或机构叠加层写入共享缓存。
- 权限负向测试必须覆盖错误码、字段集合、结果数量和跨用户/跨机构同公司场景。

## 6. 敏感操作审计

记录登录、授权变更、私密记录读写、导入/导出、审核决定、共享事实晋升/拒绝/撤回、事件纠正撤回、预算变更、Secret 引用变更和删除请求。共享决定单独保存 actor、时间、理由、原私有事件、目标共享事件、共享表述、所选证据快照和策略版本；应用角色不得更新或物理删除。通用日志保存对象 ID、结果、请求关联 ID和敏感类别，不保存完整私密正文、凭据或不必要个人信息。审计日志追加写并设置防篡改备份策略。

## 7. 文件、密钥与日志

- `data/private/`、备份、真实报告和本地 Secret 均被 `.gitignore` 排除。
- 人工导入 V1 不复制原始文件字节；批次查询、哈希和导入人保存在 RLS 表中，公共证据层只接收许可为 `public` 的来源定位、最小片段和结构化记录。
- 数据库只存文件哈希、许可和 `StorageProvider` 引用；生产存储需服务端加密和最小 IAM。
- API Key 通过部署 Secret 或环境变量注入，界面只显示末四位或引用名。
- 结构化日志对邮箱、证件、URL 查询参数和业务金额按策略脱敏；异常堆栈不得包含请求正文。
- 导出文件带访问者、范围和过期时间；高敏下载使用一次性授权并记录审计。

## 8. 备份、恢复、删除与保留

PostgreSQL 与许可允许的文件分别备份，备份加密且与主机隔离；定期做恢复演练。Demo 的建议目标为 RPO 24 小时、RTO 8 小时，仅为规划值而非 SLA。恢复后校验租户/RLS、事件证据关联、文件哈希和任务租约。

用户删除请求区分账号、租户私密数据和有合法保留义务的审计/公开事实。可删除内容先撤销访问，再按租户政策异步清除；共享公开事实不因单一基金退出而删除，但需响应来源撤回、许可到期和事实纠正。审计记录保留最小必要标识并遵循法律/合同期限。具体操作见[运维手册](12-operations-runbook.md)。

## 9. 专业顾问升级流程

1. 用户提交问题、目标公司和期望范围，形成私有任务单。
2. 管理员确认申请人基金权限、可用内部资料、价格和响应时间。
3. 顾问获得最小、限时、可审计访问；默认不能浏览同租户其他基金。
4. 研究区分引用事实与顾问分析，分析不写入事实字段。
5. 报告默认 `visibility_scope=user` 或 `fund`，导出受控。
6. 若要沉淀公共事件，必须去除投资/个人信息，确认来源许可，重新完成身份、去重、证据和审核流程。

本流程只做预留，当前不实现任务单、收费或顾问门户。

## 10. 主要威胁与控制

| 威胁 | 首要控制 |
| --- | --- |
| 跨租户/跨基金越权 | RLS、基金授权、负向权限测试、审计 |
| 研究文件含恶意内容 | 类型/大小限制、隔离解析、禁宏、文本化后再处理 |
| Prompt 注入影响事实 | 外部文本视为数据、严格 Schema、证据定位、风险闸门 |
| Secret 泄漏 | Secret 引用、日志脱敏、扫描、快速轮换 |
| 来源许可违规 | 来源级许可字段、保留策略、Provider 白名单 |
| 严重负面误报 | 身份解析、双来源规则、阻止自动升级为已确认事实、明确未确认标签、纠错撤回 |

本设计不是法律意见；进入真实数据验证前需由实际运营主体确认适用的数据、版权、网络安全和基金保密义务。

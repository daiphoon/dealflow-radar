# 10 分阶段实施计划

第 1 阶段只完成设计。本文件提出后续最小路径，不构成自动开始授权。

## 第 2 阶段：最小数据闭环

范围：Docker PostgreSQL 与 Alembic；最小租户/基金授权；公司与别名；投资关系；来源、Mock 原始文档、实体提及、候选事件、证据、审核、公司快照、刷新任务和用量台账；一个固定模板公司页面。Provider 只用 Mock，无网络。

建议实现表：`tenants`、`users`、`roles`、`user_role_assignments`、`funds`、`fund_access_grants`、`companies`、`company_aliases`、`investments`、`sources`、`raw_documents`、`entity_mentions`、`events`、`event_evidence`、`company_snapshots`、`refresh_jobs`、`review_queue`、`usage_ledger`。其余完整模型暂留文档。

验收：10 家虚构公司可从 Mock 文档幂等入库 → 解析主体 → 形成候选 → 人工审核 → 发布事件与快照 → 页面展示证据/新鲜度/授权投资概览/成本；重复运行不产生重复文档或事件；同步查询外部调用为 0；跨基金越权测试拒绝。

不做：真实 API、真实 LLM、自动 Cron、通用报表系统、通知、PDF、生产身份系统。主要风险是首版表过多和权限测试遗漏；通过只实现上述闭环、迁移审查和负向测试控制。预计新增外部成本：¥0。

## 第 3 阶段：低成本真实数据验证

范围：只选 5—10 家私有测试公司；人工研究导入、Kimi 官方/人工导出导入、DeepSeek 严格结构化抽取、少量官方公开来源；完善身份和证据审核。

验收：每个 Provider 先 `dry-run`；导入许可可追踪；文档哈希不变时 LLM 调用为 0；抽取 Schema 成功率、误报率、身份例外量和单条有效事件成本有实测；严重负面自动升级为已确认事实数为 0。

不做：批量全组合扫描、商业数据库前端抓取、无授权再分发。风险是数据许可、主体歧义、模型幻觉和费用漂移；以白名单来源、预算上限和小样本人工复核控制。预计新增外部成本：用户批准前为 ¥0，批准后按 Provider 价格配置和任务预算封顶。

## 第 4 阶段：自动调度与周报

范围：版本化 TTL、`next_check_at`、Cron、Worker 租约、关注公司、动态升降频、任务合并、固定模板周报、成本仪表盘和可选邮件/飞书通知。

验收：过期先返回后更新；并发请求只产生一个活跃任务；租约过期可恢复；预算超限转 `budget_deferred`；长期无变化降频、近期实质事件升频；周报事实水位可复现。

不做：Celery/Redis/Kafka、分钟级全网监控。风险是队列积压、重复通知和错误升频；以幂等键、投递台账、积压指标和回退策略控制。预计新增外部成本：依实测任务量、通知方式和部署资源配置，必须先做 10/50 家影子运行。

## 第 5 阶段：商业化与扩展

范围：强化多租户、正式商业数据、顾问服务、生产认证、计费、PDF、审计导出和更高并发；只有实测需要时评估 Redis/Celery、对象存储或向量检索。

验收：租户隔离渗透/权限测试、备份恢复演练、数据许可清单、预算结算、服务目标和容量测试达标；商业功能逐项 ADR 批准。

不做：未经容量证据的大规模基础设施。风险是合规义务、供应商锁定、运营审核量和成本曲线；以合同审查、Provider 抽象、容量阈值和人工服务流程控制。预计新增外部成本：待商业模型、SLA 和供应商合同确定后单独立项。

## 第 2 阶段确认结果

2026-07-14 已确认：

1. Schema 预留多租户，运行时先使用单 Demo 租户；测试同时保留第二个租户/基金用于越权验证。
2. 只使用固定虚构测试身份验证 RBAC，不实现生产登录系统。
3. 验收界面只实现公司列表与公司详情；审核队列通过 API 和自动测试覆盖。

当前最小闭环已完成 SQLite 离线测试、PostgreSQL 16 迁移与 Schema 漂移检查、迁移/应用账户分离和非所有者 RLS 负向验证，以及 API、服务端渲染和桌面浏览器视觉验收。第 2 阶段验收项已完成；第 3 阶段已用 2 家用户授权真实公司完成首轮私有、受控的人工导入验证，但仍未启用外部 Provider。

## 按需缓存与 Mock Worker V1

2026-07-15 在不启用真实 Provider、不增加数据库表和不启动自动 Worker 的前提下，先实现第 4 阶段的一条低风险基础切片：配置化 TTL 与冷却、动态新鲜度、详情过期入队、列表不扇出、活动任务合并。随后补充单次 Mock Worker：按租户领取一个任务、维护短租约和心跳、恢复过期租约、模拟无变化检查、记录零外部调用和零费用；无快照时保持未知，不编造事实。

这两条切片只验证缓存、任务数量和队列恢复，不表示已进入完整第 4 阶段。`refresh_policies` 表、预算闸门、`next_check_at`、Cron、常驻 Worker、真实 Provider 流水线、周期心跳、重试、升降频和周报仍保持未实现。

## 人工研究导入 V1

2026-07-15 实现第 3 阶段第一条零外部成本切片：机构管理员从 Git 忽略的私有目录导入公开来源 JSON；通过文件、批次、外部记录和事件指纹保证幂等；保存批次哈希、证据和身份解析血缘；所有解析成功事件进入 `in_review`，身份未解析记录进入实体提及审核，均不自动发布或更新快照。导入批次按租户 RLS 隔离，并用 `usage_ledger` 明确记录零外部调用和零费用。

该切片不实现 API 上传、CSV/Excel/Markdown、内部敏感材料、真实身份系统、Kimi/DeepSeek 或自动调度。实体提及可以安全排队但尚不能在通用事件审核接口中完成“选择公司并重建候选”。2026-07-15 首轮真实样本的 2 条记录均通过信用代码精确命中，未出现主体歧义，因此暂不扩展身份审核流程。

## 人工审核工作台 V1

2026-07-15 补齐本机最小审核呈现：受显式安全开关保护，审核员可查看候选、事实、不确定性、三类时间、五项独立评价及证据，并用必填理由批准或驳回事件；实体提及歧义保持只读。该切片不实现正式认证、纠正/撤回、身份解析、分页筛选或公开部署，也不调用外部 Provider。

## 身份优先自动路由 V1

2026-07-15 根据 ADR-0007 将新导入从“逐事件强制审核”调整为确定性路由：只有公司身份或组织关系无法唯一解析时创建人工任务；身份已验证、证据 URL 可访问、来源 A/B、可信度达标且不属于高/极高风险的事实自动发布；其余记录保存为 `unconfirmed_lead`，不进入快照也不默认创建人工任务。每条事件保留策略版本、路由原因和证据 URL 检查结果，来源只给日期时不虚构时刻。

该切片不实现全网采集、自动 Cron、LLM 抽取或付费 Provider。URL 检查受外部调用总开关与每批上限控制；关闭时安全降级为未确认线索。

## 官方工商身份核验与歧义重路由 V1

2026-07-16 根据 ADR-0008 实现 `OfficialIdentityProvider` 契约、本机官方结果 JSON 导入、政府/GSXT 域名限制、统一社会信用代码校验位、官方核验证据表与 RLS。工作台可以在默认 30 天有效期内展示与提及关联的候选；具有审核员+机构管理员角色的用户选定后，系统事务性更新公司身份、保留曾用名、解析实体提及、重建原事件/证据并复用 ADR-0007 路由。

本切片不抓取验证码、登录页或未公开接口，也不自动创建未匹配公司。由于当前未获得官方数据 API 授权，官方查询结果仍需结构化导入；获权后通过新 Provider 适配器自动化。身份决定不做外部访问，所以原来源 URL 未检查的记录会重路由为未确认线索。

## 双通道访问演进

2026-07-16 通过 ADR-0009 确认：近期采用个人查询/关注与现有基金模型共存的分步方案，长期目标为全局用户、个人订阅与 organization 机构授权并存的双通道架构。平台共享事实不等于匿名互联网公开；第一阶段仍要求登录和有效访问资格。事件事实、证据引用和原始文档分别判断作用域与许可。

### PR 1：双通道访问与数据作用域 ADR

只修改 ADR、领域模型、数据库设计、API 契约、安全设计和实施顺序。不修改业务代码、数据库模型、迁移、API、前端或本地数据。

### PR 2：数据作用域安全基线

范围：未确认线索的个人/机构所有权；原始文档和证据引用的独立作用域；所有者检查约束；保守数据回填；RLS 和跨用户、跨机构负向测试。

不做：个人搜索、watchlist、正式认证、subscription、支付或 organization 全量重构。无法可靠确认历史所有者的记录保持系统受限，不批量晋升为平台共享。

### PR 3：平台共享公司搜索和详情 API

范围：信用代码精确搜索、工商全称和已核实别名搜索、按公司 ID 读取共享详情、共享基础层与基金私有叠加层分离、无基金用户读取共享档案、搜索无结果不自动创建公司、同步请求零外部调用。

不做：模糊搜索自动绑定、个人 watchlist、前端页面、正式订阅扣次或外部 Provider。

### PR 4：最小个人查询前端

范围：公司搜索框、搜索结果、共享公司详情，以及有基金授权时的投资信息叠加。无权限的私有字段在服务端不返回，前端不以隐藏方式代替授权。

不做：个人关注、个人备注、正式认证、套餐权益、支付和机构品牌门户。

### 后续验证与兼容

PR 2、3、4 完成后，再使用 8—10 家真实公司同时验证个人和机构两条路径。当前本地影子验证基金、两家公司、投资关系和授权继续保留；两家真实公司当前为租户级记录，只有逐条人工确认身份、许可和共享范围后才能晋升为平台共享公司。每个 PR 必须可单独测试和回滚，所有 Schema 变化使用新 Alembic 迁移，不修改历史迁移。

## 1. 看板使用规则

| 状态 | 含义 |
| --- | --- |
| `本地已验证` | 本切片在本地完成规定验证；提交、合并和部署另列，不宣称已上线 |
| `已完成` | 本切片全部约定交付已达标；涉及 PR/运营时有合并或运营证据，涉及部署时另有部署验收 |
| `进行中` | 当前唯一主要工程或运营里程碑 |
| `等待决策` | 涉及方向、权限、许可、成本、认证、部署或上线的重大选择，须由项目负责人确认 |
| `待开始` | 前置闸门尚未通过，不得提前扩张范围 |
| `阻塞` | 缺少授权、数据、账户或存在不能安全绕过的问题 |
| `可选后置` | 不影响当前上线主路径，只有真实需求证据充分时才立项 |

1. 同一时间只保留一个主要里程碑；非阻塞优化记录后置，不顺手开发。
2. 数据权限、供应商授权、自动发布、目标用户、认证、部署、价格和支付等重大选择必须先给出建议与利弊，等待项目负责人决定。
3. 普通实现细节、测试方法和不改变产品边界的界面调整可在当前范围内自主决定。
4. 每个里程碑只有在验收证据、已知限制、回滚方式和下一闸门均已记录后才可关闭。
5. 已明确授权的事项在适用对象、用途和预算内不重复询问；普通技术选择自主处理。完成当前切片即交付，不自动进入下一切片。
6. 续作只需当前检查点、完整计划对应切片及相关代码；不从历史记录、附件或零散聊天重新拼接主线。

## 第 2 阶段：最小数据闭环

范围：Docker PostgreSQL 与 Alembic；最小租户/基金授权；公司与别名；投资关系；来源、Mock 原始文档、实体提及、候选事件、证据、审核、公司快照、刷新任务和用量台账；一个固定模板公司页面。Provider 只用 Mock，无网络。

不做：真实 API、真实 LLM、自动 Cron、通用报表系统、通知、PDF、生产身份系统。主要风险是首版表过多和权限测试遗漏；通过只实现上述闭环、迁移审查和负向测试控制。预计新增外部成本：¥0。

## 第 3 阶段：低成本真实数据验证

不做：批量全组合扫描、商业数据库前端抓取、无授权再分发。风险是数据许可、主体歧义、模型幻觉和费用漂移；以白名单来源、预算上限和小样本人工复核控制。预计新增外部成本：用户批准前为 ¥0，批准后按 Provider 价格配置和任务预算封顶。

## 第 4 阶段：自动调度与周报

本切片不抓取验证码、登录页或未公开接口，也不自动创建未匹配公司。政府官方查询结果仍可结构化导入；授权商业工商数据通过独立依据和 Provider 适配器接入。身份决定不做外部访问，所以原来源 URL 未检查的记录会重路由为未确认线索。

## 历史实现：天眼查授权工商身份 Provider V1

## 全局公司身份索引与已核验别名共享 V1

2026-07-19 根据 ADR-0011 修正公司身份与基金归属边界：工商主体是平台全局主实体，基金和投资关系只做私有叠加，不拥有或锁定公司。全局目录公司在管理员显式完成身份确认并发生法定名称变更时，旧工商全称以无 owner 的已核验共享别名保存；旧全称、新全称和信用代码都命中同一 `company_id`。租户级公司、内部代号、品牌名和未核实名称保持私有。

本闸门的完成条件是：个人、另一机构和两个基金复用同一公司身份，且投资叠加、私有线索、文档和证据继续隔离；无外部调用、无自动发布、无批量历史回填。通过后才进入下一项运营验证，不在本里程碑扩展模糊搜索、品牌关系或事件共享。

### 受控平台共享事实晋升闭环

2026-07-17 根据 10 家真实公司双路径影子验证结果，实现私有候选由 `platform_admin` 人工晋升为独立共享事实的最小闭环。原私有事件、导入批次、文档、owner 和研究上下文均不改变；共享事件通过全局指纹去重，展示证据只保存许可允许的来源定位、状态和短摘录，并以血缘字段指回私有证据。拒绝和撤回只追加审计，撤回后个人详情停止展示共享事实。

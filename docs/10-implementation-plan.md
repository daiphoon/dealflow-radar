# 10 分阶段实施计划

第 1 阶段只完成设计。本文件提出后续最小路径，不构成自动开始授权。

## 第 2 阶段：最小数据闭环

范围：Docker PostgreSQL 与 Alembic；最小租户/基金授权；公司与别名；投资关系；来源、Mock 原始文档、实体提及、候选事件、证据、审核、公司快照、刷新任务和用量台账；一个固定模板公司页面。Provider 只用 Mock，无网络。

建议实现表：`tenants`、`users`、`roles`、`user_role_assignments`、`funds`、`fund_access_grants`、`companies`、`company_aliases`、`investments`、`sources`、`raw_documents`、`entity_mentions`、`events`、`event_evidence`、`company_snapshots`、`refresh_jobs`、`review_queue`、`usage_ledger`。其余完整模型暂留文档。

验收：10 家虚构公司可从 Mock 文档幂等入库 → 解析主体 → 形成候选 → 人工审核 → 发布事件与快照 → 页面展示证据/新鲜度/授权投资概览/成本；重复运行不产生重复文档或事件；同步查询外部调用为 0；跨基金越权测试拒绝。

不做：真实 API、真实 LLM、自动 Cron、通用报表系统、通知、PDF、生产身份系统。主要风险是首版表过多和权限测试遗漏；通过只实现上述闭环、迁移审查和负向测试控制。预计新增外部成本：¥0。

## 第 3 阶段：低成本真实数据验证

范围：只选 5—10 家私有测试公司；人工研究导入、Kimi 官方/人工导出导入、DeepSeek 严格结构化抽取、少量官方公开来源；完善身份和证据审核。

验收：每个 Provider 先 `dry-run`；导入许可可追踪；文档哈希不变时 LLM 调用为 0；抽取 Schema 成功率、误报率、审核耗时和单条有效事件成本有实测；严重负面全部人工审核。

不做：批量全组合扫描、商业数据库前端抓取、无授权再分发。风险是数据许可、主体歧义、模型幻觉和费用漂移；以白名单来源、预算上限和小样本人工复核控制。预计新增外部成本：用户批准前为 ¥0，批准后按 Provider 价格配置和任务预算封顶。

## 第 4 阶段：自动调度与周报

范围：版本化 TTL、`next_check_at`、Cron、Worker 租约、关注公司、动态升降频、任务合并、固定模板周报、成本仪表盘和可选邮件/飞书通知。

验收：过期先返回后更新；并发请求只产生一个活跃任务；租约过期可恢复；预算超限转 `budget_deferred`；长期无变化降频、近期实质事件升频；周报事实水位可复现。

不做：Celery/Redis/Kafka、分钟级全网监控。风险是队列积压、重复通知和错误升频；以幂等键、投递台账、积压指标和回退策略控制。预计新增外部成本：依实测任务量、通知方式和部署资源配置，必须先做 10/50 家影子运行。

## 第 5 阶段：商业化与扩展

范围：强化多租户、正式商业数据、顾问服务、生产认证、计费、PDF、审计导出和更高并发；只有实测需要时评估 Redis/Celery、对象存储或向量检索。

验收：租户隔离渗透/权限测试、备份恢复演练、数据许可清单、预算结算、服务目标和容量测试达标；商业功能逐项 ADR 批准。

不做：未经容量证据的大规模基础设施。风险是合规义务、供应商锁定、运营审核量和成本曲线；以合同审查、Provider 抽象、容量阈值和人工服务流程控制。预计新增外部成本：待商业模型、SLA 和供应商合同确定后单独立项。

## 第 2 阶段确认结果

2026-07-14 已确认：

1. Schema 预留多租户，运行时先使用单 Demo 租户；测试同时保留第二个租户/基金用于越权验证。
2. 只使用固定虚构测试身份验证 RBAC，不实现生产登录系统。
3. 验收界面只实现公司列表与公司详情；审核队列通过 API 和自动测试覆盖。

当前最小闭环已完成 SQLite 离线测试与 PostgreSQL DDL 编译；真实 PostgreSQL、RLS 和视觉浏览器验收仍待完成，未进入第 3 阶段。

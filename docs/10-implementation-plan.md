## 1. 看板使用规则

| 状态 | 含义 |
| --- | --- |
| `已完成` | 验收条件已有证据，相关 PR 已合并或运营报告已确认 |
| `进行中` | 当前唯一主要工程或运营里程碑 |
| `等待决策` | 涉及方向、权限、许可、成本、认证、部署或上线的重大选择，须由项目负责人确认 |
| `待开始` | 前置闸门尚未通过，不得提前扩张范围 |
| `阻塞` | 缺少授权、数据、账户或存在不能安全绕过的问题 |
| `可选后置` | 不影响当前上线主路径，只有真实需求证据充分时才立项 |

1. 同一时间只保留一个主要里程碑；非阻塞优化记录后置，不顺手开发。
2. 数据权限、供应商授权、自动发布、目标用户、认证、部署、价格和支付等重大选择必须先给出建议与利弊，等待项目负责人决定。
3. 普通实现细节、测试方法和不改变产品边界的界面调整可在当前范围内自主决定。
4. 每个里程碑只有在验收证据、已知限制、回滚方式和下一闸门均已记录后才可关闭。

## 3. 最近完成里程碑 M4：个人用户核心使用闭环

**目标**：让无基金个人完成“精确查询 → 关注 → 识别上次查看后的变化 → 固定报告 → 回访”，同时保持共享公司与机构私有叠加分离。

工作节点：

- [x] 项目负责人确认测试默认值：每人每月查询 100 次、关注 20 家、固定报告 10 次、收录或人工更新申请合计 5 次，同公司申请冷却 24 小时；
- [x] 明确无结果只创建人工研究/收录申请，不自动创建公司、不调用天眼查或模型；
- [x] PR 1 数据模型和 RLS：单一个人关注清单、个人申请队列、与 Provider 成本台账分离的个人用量记录；
- [x] PR 1 后端和前端：关注/取消关注、无结果申请收录、共享公司申请人工更新、本人状态查看和服务端额度；
- [x] PR 1 完成浏览器验收、代码审查和 CI；
- [x] PR 2 以逐事件回执记录每个用户已看过的共享事实，避免单一时间截止点遗漏并发发布；
- [x] PR 2 生成确定性 Markdown 公司报告并执行每月 10 次服务端上限，不调用 LLM、不生成 PDF；
- [x] PR 2 完成个人/机构回归、浏览器验收和代码审查；
- [x] PR #17、#18 依序合并；持久化本地库备份后升级到 `0017`，完成个人/机构双路径、RLS、页面和恢复验收。

验收闸门：无基金个人可以关注共享公司、看到上次查看后的共享变化并生成固定报告；关注不授予读取权限；个人关注、查看水位、报告和申请对其他用户不可见；机构投资叠加不泄露；额度由后端执行；同步路径外部调用、模型 Token 和自动发布均为 0。

明确不做：多观察清单、个人备注、商业订阅/支付、PDF、消息通知、天眼查即时报告、LLM 报告、organization 重构或生产部署。当前固定额度是邀请测试策略，不是正式商业套餐。

## 第 2 阶段：最小数据闭环

范围：Docker PostgreSQL 与 Alembic；最小租户/基金授权；公司与别名；投资关系；来源、Mock 原始文档、实体提及、候选事件、证据、审核、公司快照、刷新任务和用量台账；一个固定模板公司页面。Provider 只用 Mock，无网络。

不做：真实 API、真实 LLM、自动 Cron、通用报表系统、通知、PDF、生产身份系统。主要风险是首版表过多和权限测试遗漏；通过只实现上述闭环、迁移审查和负向测试控制。预计新增外部成本：¥0。

## 第 3 阶段：低成本真实数据验证

范围：只选 5—10 家私有测试公司；人工研究导入、Kimi 官方/人工导出导入、DeepSeek 严格结构化抽取、少量官方公开来源；完善身份和证据审核。

验收：每个 Provider 先 `dry-run`；导入许可可追踪；文档哈希不变时 LLM 调用为 0；抽取 Schema 成功率、误报率、身份例外量和单条有效事件成本有实测；严重负面自动升级为已确认事实数为 0。

不做：批量全组合扫描、商业数据库前端抓取、无授权再分发。风险是数据许可、主体歧义、模型幻觉和费用漂移；以白名单来源、预算上限和小样本人工复核控制。预计新增外部成本：用户批准前为 ¥0，批准后按 Provider 价格配置和任务预算封顶。

## 第 4 阶段：自动调度与周报

范围：版本化 TTL、`next_check_at`、Cron、Worker 租约、关注公司、动态升降频、任务合并、固定模板周报、成本仪表盘和可选邮件/飞书通知。

验收：过期先返回后更新；并发请求只产生一个活跃任务；租约过期可恢复；预算超限转 `budget_deferred`；长期无变化降频、近期实质事件升频；周报事实水位可复现。

不做：Celery/Redis/Kafka、分钟级全网监控。风险是队列积压、重复通知和错误升频；以幂等键、投递台账、积压指标和回退策略控制。预计新增外部成本：依实测任务量、通知方式和部署资源配置，必须先做 10/50 家影子运行。

## 第 5 阶段：商业化与扩展

范围：强化多租户、正式商业数据、顾问服务、生产认证、计费、PDF、审计导出和更高并发；只有实测需要时评估 Redis/Celery、对象存储或向量检索。

验收：租户隔离渗透/权限测试、备份恢复演练、数据许可清单、预算结算、服务目标和容量测试达标；商业功能逐项 ADR 批准。

不做：未经容量证据的大规模基础设施。风险是合规义务、供应商锁定、运营审核量和成本曲线；以合同审查、Provider 抽象、容量阈值和人工服务流程控制。预计新增外部成本：待商业模型、SLA 和供应商合同确定后单独立项。

本里程碑仍不做：模糊搜索自动绑定、个人 watchlist/备注、正式认证、subscription/entitlement、支付、organization 全量重构或外部 Provider。

### 后续验证与兼容

安全基线和最小个人路径完成后，下一步使用 8—10 家真实公司同时验证个人和机构两条路径。当前本地影子验证基金、两家公司、投资关系和授权继续保留；两家真实公司当前为租户级记录，只有逐条人工确认身份、许可和共享范围后才能晋升为平台共享公司。所有 Schema 变化继续使用新 Alembic 迁移，不修改历史迁移。

### 受控平台共享事实晋升闭环

2026-07-17 根据 10 家真实公司双路径影子验证结果，实现私有候选由 `platform_admin` 人工晋升为独立共享事实的最小闭环。原私有事件、导入批次、文档、owner 和研究上下文均不改变；共享事件通过全局指纹去重，展示证据只保存许可允许的来源定位、状态和短摘录，并以血缘字段指回私有证据。拒绝和撤回只追加审计，撤回后个人详情停止展示共享事实。

本里程碑不恢复自动发布，不调用外部 Provider，也不实现正文语义自动核验、官方工商自动抓取、正式认证、订阅、支付、watchlist 或复杂事件版本编辑。下一步优先补齐可授权的官方工商候选入口和身份核验资料，而不是扩大自动采集范围。

# M2-F 工程闭环与验收边界

正式基线为 `c8d693c3facff59ecb7e607bd8dc2c9482dc0fc7`，schema 保持 `0036`。
本轮只使用合成 fixture 和封存片段离线回放，没有新项目研究或生产操作。

## 修改与复用

1. 获取政策及审计见 [ADR-0029](DECISIONS/ADR-0029-public-source-acquisition-policy.md)。
   默认 enforce；公开 HTTP advisory 需要明确政策和路线，访问控制与预算不放宽。
2. 合同/租赁/框架及产品批准/准入动作形成有原文支持的 typed matter；编号融资轮次
   保留其完整口径。主体、轮次/日期及明确交易不同阶段不能因相同措辞被合并。
3. 抽取、验证、比较和 prompt 分别版本化；真实新模型效果没有在本轮验证。
4. `prepare_pending_research_requests(reference_at=...)` 把明确参考值传入实际 job/
   query plan，模型输入保留同一参考字段。任务时间和心跳继续用真实时钟。
5. 评价适配逐输出关联裁决，分别记录抽取正确、证据支持、确认和交付；正式 scorecard
   汇总语义不变，不能从 published 行数反推零命中。
6. `scripts/research_validation_contract.py` 是隔离实验适配，核对实际 checkout、已加载
   模块、身份/配置/顺序/参考口径，并提供绑定合成用户/租户/公司的白名单状态投影。
   无公共写 API，不接生产，不携带正文、查询或 benchmark。
7. 九种同库研究情境复用现有 completion/API/report；不再增加第二套状态判断。
   隔离 D 没有 B 状态属于 harness gap。补齐访问控制和限流的 API/报告/组件反馈。
   过去运行记录与旧报告不回写。

## 评价边界

旧实验原件和 as-issued 回执保持字节/hash 不变；旧评分裁决契约没有建立，原成绩
不得作为新版本业务结论。旧样本永久为 REGRESSION ONLY。
40 对历史 development、四类各 10 对的合成关系及 10 份 ROUNDUP 分开计量。
作者自建合成集不是独立盲法或业务留出；困难历史字段冲突不得靠强制合并消除。
旧候选中的概念关系限制、完整摘要/逐例决定及最终 READY/HOLD 以统一私有交付包为准。

合成集由实施者生成，评测后因正式回归修复重新核验；不是独立盲法或新业务留出。

**里程碑为 `M2_F_HOLD`。** 困难历史关系 development macro-F1 为 0.24411；
保留片段的正式 PostgreSQL 回放虽补齐编号融资轮次，仍将同一事项保留为四个候选。
这不是四条独立发现，也不以强制合并来源冲突追平数字。先解决概念身份、缺字段和
阶段/冲突的归并边界，再判断能否进入全新留出。新 prompt 的真实模型效果和旧受阻 URL
的实际可读性未测；本轮不调用外部研究，也不据此改写旧业务成绩。

## 正式验证与停止

定向真实入口、非 owner PostgreSQL/RLS、报告权限/撤回/重载/幂等与内容摘要、完整后端、
Ruff/format、迁移 check、前端、Compose/镜像和秘密扫描均须实际完成。
PR 的准确 head Verify 成功是工程交付门槛；合并、生产启用和全新业务留出仍待另行授权。
本轮不改变生产预算、Provider 策略、调度、许可或 MCP。

本次采用一个联合 PR：获取失败类必须由研究状态 API、报告和前端一致接收，统一任务
契约与回归也覆盖获取、事项和读取整条链。没有复制接口或拆出需要未合并补丁才能验证
的中间版本；PR 内可按获取政策、事项关系、实验/状态契约三个逻辑变更审查。
